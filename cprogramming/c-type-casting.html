C 强制类型转换

A cast is to convert a variable from one type to another data type. For example, if you want to store a long value into a simple integer, you need to cast the long type to int type. You can use强制类型转换运算符to explicitly convert a value from one type to another, as shown below:

(type_name) expression

Please look at the following example, using a cast operator to divide one integer variable by another integer variable to obtain a floating-point number:

实例

#include <stdio.h> int main() { int sum = 17, count = 5; double mean; mean = (double) sum / count; printf("Value of mean : %f\n", mean ); }

When the above code is compiled and executed, it produces the following results:

Value of mean : 3.400000

Note here that the precedence of the cast operator is higher than division, sosumThe value of ... is first converted todoubletype, then divide by count, yielding a value of type double.

Type conversion can be implicit, performed automatically by the compiler, or explicit, by using强制类型转换运算符to specify. In programming, it is a good programming habit to use the cast operator whenever type conversion is needed.

整数提升

Integer promotion refers to converting integer types smaller thanint 或 unsigned intinteger types toint 或 unsigned intthe process. Please look at the following example, adding a character to an int:

实例

#include <stdio.h> int main() { int i = 17; char c = 'c'; /*ascii 值是 99*/ int sum; sum = i + c; printf("Value of sum : %d\n", sum ); }

When the above code is compiled and executed, it produces the following results:

Value of sum : 116

Here, the value of sum is 116, because the compiler performed integer promotion, converting the value of 'c' to its corresponding ASCII value during the actual addition operation.

The usual arithmetic conversions do not apply to assignment operators, or to the logical operators && and ||. Let's look at the following example to understand this concept:

实例

#include <stdio.h> int main() { int i = 17; char c = 'c'; /*ascii 值是 99*/ float sum; sum = i + c; printf("Value of sum : %f\n", sum ); }

When the above code is compiled and executed, it produces the following results:

Value of sum : 116.000000

Here, c is first converted to an integer, but since the final value is of type float, the usual arithmetic conversions are applied. The compiler converts i and c to floating point, adds them, and obtains a floating-point number.

    1. Assigning float, double, or long double types to an integer type: directly truncate the decimal part.

    如：

    #include <stdio.h>

int main() {
  float a = 3.8;
  int b = a;  //进行了一次隐式类型转换
  printf("a=%.2f; b=%d", a, b);
  return 0;
}

    According to the conversion rules and implicit type conversion rules, the output result is:

    a=3.80; b=3

    2. Assigning an integer type to a floating-point type (float, double, long double): fill in the significant fractional digits

    Modify the above code:

    #include <stdio.h>

int main() {
  int a = 8;
  float b = a;  //进行了一次隐式类型转换
  printf("a=%d; b=%f", a, b);
  return 0;
}

    输出：

    a=8; b=8.000000  //%f默认输出6位小数

    3. Assigning a type with shorter storage length to a type with longer storage length: fill the significant bits, and pad the remaining bits with 0

    Suppose we have the following definitions:

    char c = 56;
short num = 67;
int m;
long long int n;

    If the following operation is performed:

    m = ((int)c);
n = ((long long)num);

    Then they are stored in memory in binary format respectively as:

                                                                   00111000  //Binary of 'c'
                                                      00000000 01000011  //Binary of 'num'
                                    00000000 00000000 00000000 00111000  //Binary of 'm'
00000000 00000000 00000000 00000000 00000000 00000000 00000000 01000011  //Binary of 'n'

    4. Assigning a type with longer storage length to a type with shorter storage length: discard the high-order bits (but keep the sign), and truncate the low-order bytes for the type with shorter storage length

    假设定义：

    long long int l = 223372036854775807;

    进行赋值：

    int i = (int)l;

    They are stored in memory in binary format respectively as:

    00000011 00011001 10010011 10101111 00011101 01111011 11111111 11111111  //Binary of 'l'
                                    00011101 01111011 11111111 11111111  //Binary of 'v'

    p.s:此时的 v=494665727。

    By the way, if the last 32 bytes of the variable "l" are all 1, then v will be equal to -1.

    5. Assigning an unsigned type to a non-unsigned type: pass the value directly

    注意：If the value stored in the unsigned type is too large, after the cast it may happen that the absolute value of the non-unsigned type is not equal to the absolute value of the unsigned type's value.

    Speaking of "the value stored in the unsigned type is too large", by the way, although printf can mix %d (or %i) and %u (or %ui) when outputting int and unsigned int, it is still recommended to use %d (or %i) when outputting int, and %u (or %ui) when outputting unsigned int (and similarly for other types <such as %ul, etc.>)

    Look at an example:

    #include <stdio.h>

int main() {
  unsigned int x = 4294967295;  //这个数字为(2^32)-1, 而int类型最大存储数字的值为(2^31)-1
  int y = ((int)x);
  printf("signed of x=%d", x);  //这里有一次隐式类型转换(unsigned int => int)
  putchar('\n');
  printf("unsigned of x=%u\n", x);
  printf("signed of y=%d", y);
  return 0;
}

    However, because of implicit type conversion, the output result is:

    -1
4294967295
-1

    This output of "-1" occurs because "the value stored in the unsigned type is too large (greater than the non-unsigned type of the same kind)".

    p.s:It is not necessarily -1; it depends on the binary representation of the unsigned type's value.

    6. Assigning a non-unsigned type to an unsigned type: pass the value directly

    Here's a small trick: if you want to temporarily take the absolute value of a non-unsigned type variable whose sign is unknown, you can use the abs function, but using (unsigned)(non-unsigned type variable name) can save a little memory overhead.

    But there is also a drawback: there may be a case where unsigned - unsigned is always greater than 0 (not certain).
