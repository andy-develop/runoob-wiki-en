Go Error Handling

The Go language provides a very simple error handling mechanism through its built-in error interface.

Go's error handling uses an explicit error return approach rather than a traditional exception-handling mechanism. This design makes the code logic clearer and makes it easier for developers to handle errors explicitly during compilation or execution.

Go's error handling mainly revolves around the following mechanisms:

  1. error接口The standard error representation.
  2. 显式返回值Errors are returned through the function's return value.
  3. 自定义错误: Errors can be created through the standard library or in a custom way.
  4. panic 和 recoverHandle unrecoverable fatal errors.

error 接口

The Go standard library defines an error interface, representing an abstraction of an error.

The error type is an interface type. Here is its definition:

type error interface {
    Error() string
}
  • 实现error接口: Anything that implementsError()Any type that implements the Error() method can be used as an error.
  • Error()The method returns a string describing the error.

Using the errors package to create errors

In coding, we can generate error information by implementing the error interface type.

Create a simple error:

实例

package main

import (
    "errors"
    "fmt"
)

func main() {
    err := errors.New("this is an error")
    fmt.Println(err) // 输出：this is an error
}

Functions usually return error information as the last return value. You can use errors.New to return an error message:

func Sqrt(f float64) (float64, error) {
    if f < 0 {
        return 0, errors.New("math: square root of negative number")
    }
    // 实现
}

In the following example, we pass a negative number to Sqrt, and then get a non-nil error object. Comparing this object with nil returns true, so fmt.Println is invoked to output the error (when the fmt package handles an error, it calls the Error method). See the example call code below:

result, err:= Sqrt(-1)

if err != nil {
   fmt.Println(err)
}

Explicitly return errors

In Go, errors are usually returned as return values from functions, and developers need to explicitly check and handle them.

Explicitly return errors:

实例

package main

import (
        "errors"
        "fmt"
)

func divide(a, b int) (int, error) {
        if b == 0 {
                return 0, errors.New("division by zero")
        }
        return a / b, nil
}

func main() {
        result, err := divide(10, 0)
        if err != nil {
                fmt.Println("Error:", err)
        } else {
                fmt.Println("Result:", result)
        }
}

输出：

Error: division by zero

自定义错误

By defining custom types, you can extend the error interface.

Custom error types:

实例

package main

import (
        "fmt"
)

type DivideError struct {
        Dividend int
        Divisor  int
}

func (e *DivideError) Error() string {
        return fmt.Sprintf("cannot divide %d by %d", e.Dividend, e.Divisor)
}

func divide(a, b int) (int, error) {
        if b == 0 {
                return 0, &DivideError{Dividend: a, Divisor: b}
        }
        return a / b, nil
}

func main() {
        _, err := divide(10, 0)
        if err != nil {
                fmt.Println(err) // 输出：cannot divide 10 by 0
        }
}

The fmt package and error formatting.

fmtThe package provides formatted output support for errors:

  • %v: Default format.
  • %+v: If supported, display detailed error information.
  • %sOutput as a string.

实例

package main

import (
    "fmt"
)

// 定义一个 DivideError 结构
type DivideError struct {
    dividee int
    divider int
}

// 实现 `error` 接口
func (de *DivideError) Error() string {
    strFormat := `
    Cannot proceed, the divider is zero.
    dividee: %d
    divider: 0
`
    return fmt.Sprintf(strFormat, de.dividee)
}

// 定义 `int` 类型除法运算的函数
func Divide(varDividee int, varDivider int) (result int, errorMsg string) {
    if varDivider == 0 {
            dData := DivideError{
                    dividee: varDividee,
                    divider: varDivider,
            }
            errorMsg = dData.Error()
            return
    } else {
            return varDividee / varDivider, ""
    }

}

func main() {

    // 正常情况
    if result, errorMsg := Divide(100, 10); errorMsg == "" {
            fmt.Println("100/10 = ", result)
    }
    // 当除数为零的时候会返回错误信息
    if _, errorMsg := Divide(100, 0); errorMsg != "" {
            fmt.Println("errorMsg is: ", errorMsg)
    }

}

Run the above program, the output is:

100/10 =  10
errorMsg is:  
    Cannot proceed, the divider is zero.
    dividee: 100
    divider: 0

使用 errors.Is 和 errors.As

Starting from Go 1.13,errors包引入了errors.Is 和 errors.AsUsed for handling error chains:

errors.Is

Check whether an error is a specific error or was wrapped from that error.

实例

package main

import (
        "errors"
        "fmt"
)

var ErrNotFound = errors.New("not found")

func findItem(id int) error {
        return fmt.Errorf("database error: %w", ErrNotFound)
}

func main() {
        err := findItem(1)
        if errors.Is(err, ErrNotFound) {
                fmt.Println("Item not found")
        } else {
                fmt.Println("Other error:", err)
        }
}

errors.As

Convert the error to a specific type for further processing.

实例

package main

import (
        "errors"
        "fmt"
)

type MyError struct {
        Code int
        Msg  string
}

func (e *MyError) Error() string {
        return fmt.Sprintf("Code: %d, Msg: %s", e.Code, e.Msg)
}

func getError() error {
        return &MyError{Code: 404, Msg: "Not Found"}
}

func main() {
        err := getError()
        var myErr *MyError
        if errors.As(err, &myErr) {
                fmt.Printf("Custom error - Code: %d, Msg: %s\n", myErr.Code, myErr.Msg)
        }
}

panic 和 recover

Go's panic is used to handle unrecoverable errors, and recover is used to recover from a panic.

panic:

  • Causes the program to crash and outputs stack information.
  • Often used when the program cannot continue running.

recover:

  • 捕获panicavoiding program crashes.

实例

package main

import "fmt"

func safeFunction() {
        defer func() {
                if r := recover(); r != nil {
                        fmt.Println("Recovered from panic:", r)
                }
        }()
        panic("something went wrong")
}

func main() {
        fmt.Println("Starting program...")
        safeFunction()
        fmt.Println("Program continued after panic")
}

Run the above code, the output is:

Starting program...
Recovered from panic: something went wrong
Program continued after panic

    Here we should introduce panic and recover; one is used to actively throw an error, and the other is used to catch errors thrown by panic.

    概念

    panic and recover are two built-in functions in Go. These two built-in functions are used to handle Go runtime errors. panic is used to actively throw an error, and recover is used to catch the error thrown by panic.

    • 引发panicThere are two cases: one is that the program actively calls [panic]; the other is that a runtime error occurs in the program and is detected by the runtime, causing the program to exit.
    • 发生panicAfter [recover] is called, the program will resume from the callpanicto the location of the function where [recover was called] or where [panic] occurred.panicimmediately returns at that place, and executes the function's ... layer by layer upwarddeferstatements, then prints the function call stack layer by layer, until it isrecoverCapture or run to the outermost function.
    • panicIt can be thrown not only during the normal flow of a function, but also indefer[recover] can also be called again within the [panic] logic,panic或抛出panic。defer里面的panicso that a subsequently executed [recover] candefer捕获。
    • recover用来捕获panic，阻止panicContinue passing upward.recover()和deferUsed together, butdeferIt can only be caught if it is directly called in the later function body.panicterminate the exception; otherwise, it returnsnilnil, and the exception continues to propagate outward.

    例子1

    //以下捕获失败
defer recover()
defer fmt.Prinntln(recover)
defer func(){
    func(){
        recover() //无效，嵌套两层
    }()
}()

//以下捕获有效

    recover()
}()

func except(){
    recover()
}
func test(){
    defer except()
    panic("runtime error")
}

    例子2

    Multiple panics will only catch the last one:

    package main
import "fmt"
func main(){
    defer func(){
        if err := recover() ; err != nil {
            fmt.Println(err)
        }
    }()
    defer func(){
        panic("three")
    }()
    defer func(){
        panic("two")
    }()
    panic("one")
}

    使用场景

    In general, there are two cases where it is used:

    • When the program encounters an error that prevents it from continuing execution, it throws an error and actively terminates.
    • When debugging a program, use panic to print the stack trace to make it easier to locate errors.

    Through my repeated experiments, here are a few points about panic, defer, and recover.

    • 1. Before panic is recovered and in the function stack level where recover catches it, code after panic will not execute; once caught by recover, the outer function stack code returns to normal, and all code will execute.
    • 2. After panic, subsequent code is no longer executed; defer is executed immediately in reverse order, and the panic spreads outward through function stack levels layer by layer; defer is similar to finally.
    • 3. When using recover to catch panic, defer must be declared before panic; otherwise, since code after panic cannot execute, recover cannot be performed either.
    package main

import (
"fmt"
)

func main() {
  fmt.Println("外层开始")
  defer func() {
    fmt.Println("外层准备recover")
    if err := recover(); err != nil {
      fmt.Printf("%#v-%#v\n", "外层", err) // err已经在上一级的函数中捕获了，这里没有异常，只是例行先执行defer，然后执行后面的代码
    } else {
      fmt.Println("外层没做啥事")
    }
    fmt.Println("外层完成recover")
  }()
  fmt.Println("外层即将异常")
  f()
  fmt.Println("外层异常后")
  defer func() {
    fmt.Println("外层异常后defer")
  }()
}

func f() {
  fmt.Println("内层开始")
  defer func() {
    fmt.Println("内层recover前的defer")
  }()

  defer func() {
    fmt.Println("内层准备recover")
    if err := recover(); err != nil {
      fmt.Printf("%#v-%#v\n", "内层", err) // 这里err就是panic传入的内容
    }

    fmt.Println("内层完成recover")
  }()

  defer func() {
    fmt.Println("内层异常前recover后的defer")
  }()

  panic("异常信息")

  defer func() {
    fmt.Println("内层异常后的defer")
  }()

  fmt.Println("内层异常后语句") //recover捕获的一级或者完全不捕获这里开始下面代码不会再执行
}
