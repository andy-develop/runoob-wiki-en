Go language slice (Slice)

Go language slices are an abstraction over arrays.

The length of Go arrays cannot be changed, so in specific scenarios such a collection is not very suitable. Go provides a flexible and powerful built-in type: slice ("dynamic array"). Compared with arrays, the length of a slice is not fixed; elements can be appended, and appending may increase the capacity of the slice.

定义切片

You can declare an array of unspecified size to define a slice:

var identifier []type

Slices do not need to specify a length.

或使用make()Function to create a slice:

var slice1 []type = make([]type, len)

也可以简写为

slice1 := make([]type, len)

You can also specify the capacity, wherecapacityis an optional parameter.

make([]T, length, capacity)

Here len is the length of the array and also the initial length of the slice.

切片初始化

s :=[] int {1,2,3 }

Directly initialize the slice,[]Indicates that it is a slice type,{1,2,3}The initialization values are, in order:1,2,3，其cap=len=3。

s := arr[:]

初始化切片s, is a reference to the array arr.

s := arr[startIndex:endIndex]

Create a new slice from the elements of arr from index startIndex to endIndex-1.

s := arr[startIndex:]

When endIndex is defaulted, it means up to the last element of arr.

s := arr[:endIndex]

When startIndex is defaulted, it means starting from the first element of arr.

s1 := s[startIndex:endIndex]

Initialize slice s1 through slice s.

s :=make([]int,len,cap)

Through the built-in functionmake()初始化切片s，[]intDenotes a slice whose element type is int.

len() 和 cap() 函数

Slices are indexable, and their length can be obtained by the len() method.

Slices provide the cap() method for calculating capacity, which can measure how long a slice can reach at most.

The following are specific examples:

实例

package main

import "fmt"

func main() {
   var numbers = make([]int,3,5)

   printSlice(numbers)
}

func printSlice(x []int){
   fmt.Printf("len=%d cap=%d slice=%v\n",len(x),cap(x),x)
}

The output of the above example is:

len=3 cap=5 slice=[0 0 0]

append() 和 copy() 函数

If you want to increase the capacity of a slice, you must create a new larger slice and copy the contents of the original slice into it.

The following code describes the copy method for copying slices and the append method for appending new elements to a slice.

实例

package main

import "fmt"

func main() {
   var numbers []int
   printSlice(numbers)

   /* 允许追加空切片 */
   numbers = append(numbers, 0)
   printSlice(numbers)

   /* 向切片添加一个元素 */
   numbers = append(numbers, 1)
   printSlice(numbers)

   /* 同时添加多个元素 */
   numbers = append(numbers, 2,3,4)
   printSlice(numbers)

   /* 创建切片 numbers1 是之前切片的两倍容量*/
   numbers1 := make([]int, len(numbers), (cap(numbers))*2)

   /* 拷贝 numbers 的内容到 numbers1 */
   copy(numbers1,numbers)
   printSlice(numbers1)  
}

func printSlice(x []int){
   fmt.Printf("len=%d cap=%d slice=%v\n",len(x),cap(x),x)
}

The output of executing the above code is:

len=1 cap=1 slice=[0]
len=2 cap=2 slice=[0 1]
len=5 cap=6 slice=[0 1 2 3 4]
len=5 cap=12 slice=[0 1 2 3 4]

    Internal structure of a slice:

    struct Slice
{   
    byte*    array;       // actual data
    uintgo    len;        // number of elements
    uintgo    cap;        // allocated number of elements

};

    The first field represents the pointer to the array, which is the pointer to the real data; the second represents the length of the slice; the third represents the capacity of the slice.

    所以unsafe.Sizeof(切片)It is always 24.

    When using a slice as a parameter, what is passed is the value itself, but its content isbyte* array, what is actually passed is a reference, so it can be modified inside the function. But if you append to the slice itself, and this causes the slice to expand, what actually expands is a copy of the slice inside the function, while the slice outside the function does not change.

    package main

"fmt"
"unsafe"

    slice_value(slice_test)
    fmt.Printf("main:%#v,%#v,%#v\n", slice_test, len(slice_test), cap(slice_test))
    slice_ptr(&slice_test)
    fmt.Printf("main:%#v,%#v,%#v\n", slice_test, len(slice_test), cap(slice_test))
    fmt.Println(unsafe.Sizeof(slice_test))
}

func slice_value(slice_test []int) {
    slice_test[1] = 100                // 函数外的slice确实有被修改

    I think the previous answers to the question of why cap becomes 6 are not quite correct.

    When adding 6 elements, according to the above statements, the cap value should be 12 and 9 respectively; but after practice, the cap value obtained is 8, which shows that the above statements are not comprehensive.

    After experiments with multiple data points, I found that the value of cap can only be even.

    The experimental data is as follows:

    When the initial cap is 2: adding 2 elements makes cap 4, adding 3 elements makes cap 6, adding 4 elements makes cap 6, adding 5 elements makes cap 8, adding 6 elements makes cap 8, adding 7 elements makes cap 10, adding 8 elements makes cap 10...

    When the initial cap is 1: adding 2 elements makes cap 4, adding 3 elements makes cap 4, adding 4 elements makes cap 6, adding 5 elements makes cap 6, adding 6 elements makes cap 8, adding 7 elements makes cap 8, adding 8 elements makes cap 10...

    So the rule I summarized is: after adding elements, when len[list]+len[params] > cap, the value of cap needs to be modified.

    若len[list]+len[params]为偶数，则cap=len[list]+len[params]

    若len[list]+len[params]为奇数，则cap=len[list]+len[params]+1

    The above is personal experience summary.

    Regarding the question of why cap becomes 6, I think the explanation above is also wrong, haha.

    1. When adding multiple elements at the same time:

    len(list)+len([params]) 为偶数：cap=len(list)+len([params])

len(list)+len([params]) 为奇数：cap=len(list)+len([params])+1

    That is, cap is always an even number.

    2. When adding elements one by one:

    len(list)+1<=cap:   cap=cap

len(list)+1>cap:     cap=2*cap

    That is, cap always increases by a factor of 2 (and is also even).

    You can check the source code in $GOROOT/src/runtime/slice.go, where the expansion-related code is as follows:

    newcap := old.cap
doublecap := newcap + newcap
if cap > doublecap {
    newcap = cap
} else {
    if old.len < 1024 {
        newcap = doublecap
    } else {
        // Check 0 < newcap to detect overflow
        // and prevent an infinite loop.
        for 0 < newcap && newcap < cap {
            newcap += newcap / 4
        }
        // Set newcap to the requested cap when
        // the newcap calculation overflowed.
        if newcap <= 0 {
            newcap = cap
        }
    }
}

    From the above code, the following can be seen:

    • First, determine: if the newly requested capacity (cap) is greater than 2 times the old capacity (old.cap), then the final capacity (newcap) is the newly requested capacity (cap).
    • Otherwise, determine: if the old slice's length is less than 1024, then the final capacity (newcap) is twice the old capacity (old.cap), i.e., (newcap = doublecap),
    • Otherwise, if the old slice length is greater than or equal to 1024, the final capacity (newcap) starts from the old capacity (old.cap) and increases by 1/4 of the original value in a loop, i.e., (newcap=old.cap, for { newcap += newcap/4 }) until the final capacity (newcap) is greater than or equal to the newly requested capacity (cap), i.e., (newcap >= cap).
    • If the calculated final capacity (cap) overflows, then the final capacity (cap) is the newly requested capacity (cap).

    It should be noted that slice expansion is also handled differently depending on the type of elements in the slice, for exampleint和stringThe handling of types is different.
