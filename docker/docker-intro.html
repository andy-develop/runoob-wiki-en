Docker Basic Concepts

What is containerization technology

Containers share the host kernel, making them lightweight, isolated, and efficient—unlike virtual machines, which require a full operating system. The following diagram shows the basic architecture of Docker containers:

  • The upper layer consists of multiple containers (App A-F), each container independently runs an application.
  • The middle layer is Docker, which is responsible for managing these containers.
  • The bottom layer is the host operating system (Host OS) and infrastructure, providing hardware and system support for containers.

1. Pain Points of Traditional Application Deployment

In traditional application deployment, we often encounter the following problems:

  • 环境不一致: Applications run normally in the development environment but encounter issues in the testing or production environment
  • Complex dependency management: Different applications require different versions of runtimes, library files, etc.
  • Low resource utilization: Traditional virtual machines require a full operating system, consuming a large amount of resources.
  • 部署复杂: Requires manual environment configuration and dependency installation, which is error-prone.

2. Solutions with Containerization Technology

Containerization technology solves these problems in the following ways:

  • 环境标准化: Package the application along with its dependencies to ensure consistent operation in any environment
  • 轻量级: Containers share the host operating system kernel, making them lighter than virtual machines.
  • 快速部署: Containers can start within seconds, greatly improving deployment efficiency.
  • 可移植性: Build once, run anywhere

3. Core Concepts of Containerization

Containerization follows the philosophy of "immutable infrastructure":

  • Applications and environments are packaged into immutable images.
  • Use the same image for every deployment
  • Configuration is injected via environment variables or configuration files.
  • Fix issues by rebuilding the image rather than modifying running containers

Docker Core Concepts

1、镜像 (Image)

定义: An image is a read-only template that contains everything needed to run an application: code, runtime, library files, environment variables, and configuration files.

特点：

  • 分层存储: An image consists of multiple layers, each representing a modification.
  • 只读性: The image itself is read-only and cannot be modified directly.
  • 可复用: The same image can be used to create multiple containers
  • 版本管理: Version management is performed using tags.

类比理解: An image is like an installer or template; it defines everything needed to run the application, but it cannot run directly by itself.

2、容器 (Container)

定义: A container is a running instance of an image, a lightweight, portable execution environment.

特点：

  • 隔离性: Each container has its own file system, network, and process space.
  • 临时性: Containers can be created, started, stopped, and deleted.
  • 可写层: A container adds a writable layer on top of the image.
  • 进程级: Usually one main process runs inside a container

类比理解: If the image is a class, then the container is an object instance. One image can create multiple containers, just as one class can create multiple objects.

3、仓库 (Repository)

定义: A repository is a place to store and distribute images, and it can contain multiple versions of an image.

分类：

  • 公共仓库: Such as Docker Hub, which anyone can use.
  • 私有仓库: Set up within an enterprise to store private images.
  • 官方仓库: Image repositories maintained by the software vendor

Registry vs Repository：

  • Registry: Registry servers, such as Docker Hub
  • Repository: Specific image repositories, such as nginx, mysql.

3. Use Case Comparison

VM applicable scenarios：

  • Requires a fully isolated environment
  • Run applications of different operating systems
  • Requires hardware-level security isolation

Scenarios Suited for Docker Containers：

  • 微服务架构
  • CI/CD pipeline
  • Rapid application deployment and scaling
  • Development environment standardization

Docker's advantages and application scenarios.

主要优势

1. Environment Consistency

  • 问题解决: The "it works on my machine" problem
  • 实现方式: Application and environment are packaged together
  • 价值: Reduces environment-related bugs and deployment issues

2. Lightweight and Efficient

  • 资源利用: Uses fewer resources than virtual machines
  • 启动速度: Second-level startup time
  • 密度: A single machine can run more application instances

3. Portability

  • 跨平台：Linux、Windows、macOS都支持
  • 云原生: Migration across various cloud platforms
  • 混合环境: Develop locally, deploy in the cloud

4. Version Control and Rollback

  • 镜像版本: Each version has a corresponding image
  • 快速回滚: Quickly roll back to the previous version when issues occur
  • A/B测试: Run different versions simultaneously for comparison

5. Scalability

  • 水平扩展: Quickly create more container instances
  • 弹性伸缩: Automatically adjusts the number of containers based on load
  • 微服务: Service splitting and independent deployment

Typical application scenarios

1. Microservices Architecture

  • 服务拆分: Each microservice is independently containerized
  • 独立部署: Services can be independently updated and scaled
  • 技术栈自由: Different services can use different technologies

2. CI/CD pipeline

  • 构建环境: Standardized build environment
  • 测试隔离: Each test runs in an independent container
  • 部署一致性: The same image is deployed in different environments

3. Development Environment Standardization

  • 快速搭建: New members quickly obtain a development environment
  • 版本同步: The team uses the same development environment
  • 依赖管理: Avoids local environment conflicts

4. Application Modernization

  • 遗留系统: Containerizing traditional applications
  • 云迁移: Helps migrate applications to cloud platforms
  • 混合云: Portability across different cloud environments

Docker Architecture Components

整体架构图

Docker Client

功能：

  • The main ways users interact with Docker.
  • Receives user commands and sends them to the Docker Daemon.
  • Can communicate with a remote Docker Daemon.

常用命令：

  • docker run- Run container
  • docker build- Build image
  • docker pull- Pull image
  • docker ps- View container status

Docker Daemon

功能：

  • Docker's core service process
  • Manages images, containers, networks, and storage volumes
  • Listens for and processes Docker API requests.

主要职责：

  • Image management (building, storing, distributing)
  • Container lifecycle management
  • 网络管理
  • 数据卷管理
  • Communicate with Registry

Docker Engine

组成：

  • Docker Client + Docker Daemon + REST API
  • It is a core component of Docker

工作流程：

  1. Client sends commands to Daemon
  2. The Daemon parses and executes commands
  3. Interacts with the Registry (if needed).
  4. Manages local images and containers
  5. Return results to Client

Docker Registry

作用：

  • Stores and distributes Docker images
  • Provides image version management
  • Supports public and private registries

Docker Hub特点：

  • Official public Registry
  • Contains a large number of pre-built images
  • Supports auto-build functionality
  • Free and paid services

Docker Development History

Key milestones

  • 2013年: Docker open-source release
  • 2014年: Docker 1.0 released, available for production use.
  • 2016年: Docker Swarm released, with built-in orchestration features.
  • 2017年: Docker is divided into CE (Community Edition) and EE (Enterprise Edition).
  • 2019年: Docker Desktop released, improving the developer experience.

Ecosystem development

  • 容器编排: Kubernetes becomes the de facto standard.
  • 容器运行时: containerd, CRI-O and other alternatives
  • 镜像格式: OCI standard specification
  • 安全工具: Container security scanning and monitoring tools
