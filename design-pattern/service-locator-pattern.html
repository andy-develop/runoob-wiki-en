Service Locator Pattern

The Service Locator Pattern is used when we want to locate various services using JNDI queries. Considering that performing a JNDI lookup for a service is expensive, the Service Locator Pattern makes full use of caching technology. When a service is first requested, the service locator looks up the service in JNDI and caches the service object. When the same service is requested again, the service locator looks it up in its cache, which can greatly improve application performance. The following are the entities of this design pattern.

  • 服务（Service）- The service that actually handles requests. References to such services can be found in the JNDI server.
  • Context / 初始的 Context- The JNDI Context holds references to the services to be looked up.
  • 服务定位器（Service Locator）- The service locator is a single point of contact for obtaining services through JNDI lookup and service caching.
  • 缓存（Cache）- The cache stores references to services in order to reuse them.
  • 客户端（Client）Client is an object that invokes services through ServiceLocator.

概要

意图

Used to provide a centralized service access point in an application for obtaining various services or resources.

Main problem solved

  • Solves the problem of avoiding hard-coded service access logic when an application needs to access various services or resources.

使用场景

  • When an application needs to access multiple external services or resources and wants to centrally manage this access logic.

实现方式

  • Service Locator InterfaceDefine methods for obtaining services.
  • Service Locator Implementation: Implement the service locator interface, encapsulating service lookup and access logic.
  • 服务接口Define the service interface or contract.
  • 具体服务: Implement the service interface, providing specific service functionality.

关键代码

  • 服务定位器Contains logic to find and return the requested service instance.
  • 服务接口Define an abstract representation of the service.

应用实例

  • Enterprise Application: The application uses the service locator to access database services, message queue services, etc.

优点

  1. Decouple service access: Separates service access logic from the business logic that uses the services.
  2. 集中管理: Service access points are centrally managed, making maintenance and extension easier.
  3. 灵活性Easy to add, modify, or replace services.

缺点

  • 性能问题: The service locator may introduce performance overhead, especially when a lookup is performed on every service request.
  • 过度使用: May lead to misuse of the design pattern, thereby hiding the system structure.

使用建议

  • When an application needs to access multiple services in a flexible and maintainable way, consider using the Service Locator Pattern.

注意事项

  • Avoid over-reliance on the service locator, as it may mask the system's dependencies, making debugging and optimization difficult.

Contains several main roles

  1. Service Locator Interface：

    • Define methods for obtaining services.

  2. 服务定位器实现（Service Locator Implementation）：

    • Implement the service locator interface, encapsulating service lookup and access logic.

  3. 服务接口（Service Interface）：

    • Define an abstract representation of the service.

  4. 具体服务（Concrete Service）：

    • Implement the service interface, providing specific service functionality.

  5. Client：

    • Use the service locator to access the required services.

The Service Locator Pattern helps simplify service access logic and improve application flexibility and maintainability by providing a centralized service access point.

实现

我们将创建ServiceLocator、InitialContext、Cache、ServiceVarious objects representing entities.Service1 和 Service2Represents an entity service.

ServiceLocatorPatternDemoThe class here acts as a client and will useServiceLocatorTo demonstrate the Service Locator design pattern.

步骤 1

Create the service interface Service.

Service.java

public interface Service { public String getName(); public void execute(); }

步骤 2

Creates an entity service.

Service1.java

public class Service1 implements Service { public void execute(){ System.out.println("Executing Service1"); } @Override public String getName() { return "Service1"; } }

Service2.java

public class Service2 implements Service { public void execute(){ System.out.println("Executing Service2"); } @Override public String getName() { return "Service2"; } }

步骤 3

为 JNDI 查询创建 InitialContext。

InitialContext.java

public class InitialContext { public Object lookup(String jndiName){ if(jndiName.equalsIgnoreCase("SERVICE1")){ System.out.println("Looking up and creating a new Service1 object"); return new Service1(); }else if (jndiName.equalsIgnoreCase("SERVICE2")){ System.out.println("Looking up and creating a new Service2 object"); return new Service2(); } return null; } }

步骤 4

Create a cache Cache.

Cache.java

import java.util.ArrayList; import java.util.List; public class Cache { private List<Service> services; public Cache(){ services = new ArrayList<Service>(); } public Service getService(String serviceName){ for (Service service : services) { if(service.getName().equalsIgnoreCase(serviceName)){ System.out.println("Returning cached "+serviceName+" object"); return service; } } return null; } public void addService(Service newService){ boolean exists = false; for (Service service : services) { if(service.getName().equalsIgnoreCase(newService.getName())){ exists = true; } } if(!exists){ services.add(newService); } } }

步骤 5

Create a service locator.

ServiceLocator.java

public class ServiceLocator { private static Cache cache; static { cache = new Cache(); } public static Service getService(String jndiName){ Service service = cache.getService(jndiName); if(service != null){ return service; } InitialContext context = new InitialContext(); Service service1 = (Service)context.lookup(jndiName); cache.addService(service1); return service1; } }

步骤 6

使用ServiceLocatorTo demonstrate the Service Locator design pattern.

ServiceLocatorPatternDemo.java

public class ServiceLocatorPatternDemo { public static void main(String[] args) { Service service = ServiceLocator.getService("Service1"); service.execute(); service = ServiceLocator.getService("Service2"); service.execute(); service = ServiceLocator.getService("Service1"); service.execute(); service = ServiceLocator.getService("Service2"); service.execute(); } }

Run the program, output result:

Executing Service1
