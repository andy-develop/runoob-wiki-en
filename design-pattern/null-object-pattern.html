空对象模式

In the Null Object Pattern, a null object replaces the check for NULL object instances. Instead of checking for null values, the Null object responds with a relationship that does nothing. Such a Null object can also provide default behavior when data is unavailable.

In the Null Object Pattern, we create an abstract class that specifies various operations to be performed and entity classes that extend this class, and also create a null object class that does not implement anything for the class. This null object class is seamlessly used in places where null checks are needed.

概要

意图

Use a null object instead of a null value. The null object implements the same interface, but performs no operations or provides default operations for requests.

Main problems solved

  • The Null Object Pattern solves problems that may arise from using null values in a system, such as NullPointerException exceptions.
  • It allows the system to continue running with a "safe" null object when no suitable object is available, rather than failing.

使用场景

  • When the system needs to handle null objects, but also wants to avoid null checks or the handling of null values.

实现方式

  • 定义协议：Define a protocol or interface that specifies the behaviors to be implemented.
  • Creating concrete objects：Concrete objects that implement the protocol and provide actual behavior.
  • 创建空对象：Also implement the same protocol, but provide an "empty" implementation, i.e., no meaningful operations are performed.

关键代码

  • 协议或接口：Specifies the methods that the object needs to implement.
  • 具体对象：Implement the protocol and contain actual business logic.
  • 空对象：Implement the protocol, but the method implementations are empty or default behaviors.

应用实例

  • 日志系统：In a logging system, a null object may represent a logger that performs no operations.
  • 默认用户：In a system, if there is currently no user, an empty user object can be used instead of null.

优点

  1. Avoiding null checks：Eliminates null checks in the code.
  2. Simplifying client code：Clients can directly call methods regardless of whether the object is null.
  3. 扩展性：Adding new concrete objects is transparent to clients, requiring no modification of existing code.

缺点

  • May hide errors：Using null objects may hide errors or exceptional conditions, making debugging difficult.
  • Increases design complexity：A null object needs to be implemented for every interface that may return null.

使用建议

  • When the system needs to handle null values, but also wants to simplify error handling and avoid null checks, consider using the Null Object Pattern.

注意事项

  • The Null Object Pattern should be used with caution to ensure that it does not hide errors or mask the true state of the system.
  • A null object should provide the same interface as concrete objects, so that client code can use it without any changes.

结构

The Null Object Pattern includes the following main roles:

  • 抽象对象（Abstract Object）：Defines the interface expected by the client. This interface can be an abstract class or an interface.

  • 具体对象（Concrete Object）：Concrete classes that implement the abstract object interface. These classes provide real behavior.

  • 空对象（Null Object）：A null object class that implements the abstract object interface. This class provides default no-op behavior to be used when the object is unavailable or not applicable. It can serve as a substitute for concrete objects, replacing null checks in client code.

    PHP代码：

    <?php
abstract class AbstractCustomer{

  protected $name;
  public abstract function isNil();
  public abstract  function getName();
}


class RealCustomer extends AbstractCustomer {


    public function __construct($name)
    {
        $this->name = $name;    
    }

   public function getName() {
      return $this->name;   
   }


   public function isNil() {
      return false;   
   }

}

class NullCustomer extends AbstractCustomer {

    public function getName() {

       return "Not Available in Customer Database";    
    }


   public function isNil() {
      return true;   
   }


}
class CustomerFactory {

    #PHP中final不能修饰变量，但可以是类和方法
    public static  $names = ["Rob", "Joe", "Julie"];   

    public static function  getCustomer($name){
       //foreach更方便，如果说有点学习点地方就是静态变量必须用静态方法调用，self::$value 

        for ($i = 0; $i < count(self::$names); $i++) {
            if (self::$names[$i] == $name){
                return new RealCustomer($name);            
             }
        }
          return new NullCustomer();       
   }
}

class NullPatternDemo {
    public static function main() {

     $customer1 = CustomerFactory::getCustomer("Rob");     
     $customer2 = CustomerFactory::getCustomer("Bob");     
     $customer3 = CustomerFactory::getCustomer("Julie");     
     $customer4 = CustomerFactory::getCustomer("Laura");

     echo $customer2->getName().PHP_EOL;     
     echo $customer3->getName().PHP_EOL;     
     echo $customer4->getName().PHP_EOL;    
    }
}
