工厂模式

Factory Pattern is one of the most commonly used design patterns in Java. It provides a way to create objects, separating the process of creating objects from the process of using objects.

The Factory Pattern provides a way to create objects without specifying the concrete class to be created.

By using the factory pattern, the object creation logic can be encapsulated within a factory class rather than instantiating objects directly in client code, which improves code maintainability and extensibility.

Types of Factory Pattern

1、简单工厂模式（Simple Factory Pattern）：

  • The Simple Factory Pattern is not a formal design pattern, but it is the foundation of the Factory Pattern. It uses a single factory class to create different objects, determining which type of object to create based on the parameters passed in.

2、工厂方法模式（Factory Method Pattern）：

  • The Factory Method pattern defines an interface for creating objects, but lets subclasses decide which class to instantiate. It defers object creation to subclasses.

3、抽象工厂模式（Abstract Factory Pattern）：

  • The Abstract Factory pattern provides an interface for creating a family of related or interdependent objects without specifying their concrete classes.

概要

意图

Define an interface for creating objects, and let subclasses decide which concrete class to instantiate. The factory pattern defers the object creation process to subclasses.

主要解决

The issue of interface selection.

何时使用

When we need to create different instances under different conditions.

如何解决

By having subclasses implement the factory interface, an abstract product is returned.

关键代码

The object creation process is implemented in subclasses.

应用实例

  1. 汽车制造: You need a car; you just pick it up from the factory, without needing to care about the manufacturing process and internal implementation of the car.
  2. HibernateWhen switching databases, you only need to change the Dialect and the database Driver to switch between different databases.

优点

  1. The caller only needs to know the name of the object to create it.
  2. High extensibility: if a new product needs to be added, you only need to extend a factory class.
  3. The specific implementation of the product is hidden; the caller only cares about the product interface.

缺点

Each time a product is added, a concrete class and a corresponding factory need to be added, causing the number of classes in the system to multiply, increasing the system's complexity and dependency on concrete classes.

使用场景

  1. 日志记录: Logs may be recorded to a local hard disk, system events, remote servers, etc. Users can choose where to record the logs.
  2. 数据库访问: When the user does not know which database the final system will use, or when the database may change.
  3. Framework design for connecting to a server.: It is necessary to support three protocols: "POP3", "IMAP", "HTTP". These three protocols can be used as product classes that together implement an interface.

注意事项

The Factory Pattern is suitable for scenarios where complex objects are generated. If the object is relatively simple and can be created with `new`, there is no need to use the Factory Pattern. Using the Factory Pattern introduces a factory class and increases system complexity.

结构

The Factory Pattern includes the following main roles:

  • Abstract Product: Defines the common interface or abstract class of the product. It can be the parent class or interface of concrete product classes, specifying the common methods of product objects.
  • Concrete Product: Implements the abstract product interface, defining the specific behavior and properties of a concrete product.
  • Abstract Factory: Declares abstract methods for creating products; it can be an interface or an abstract class. It can have multiple methods for creating different types of products.
  • Concrete Factory: Implements the abstract factory interface and is responsible for actually creating concrete product objects.

    public enum Factory {
    CIRCLE(new Circle(),"CIRCLE"),
    RECTANGLE(new Rectangle(),"RECTANGLE"),
    SQUARE(new Square(),"SQUARE");
    
    // 成员变量  
    private Shape shape;  
    private String name;  
    
    // 普通方法  
    public static Shape getShape(String name) {  
        for (Factory c : Factory.values()) {  
            if (c.name == name) {  
                return c.shape;  
            }  
        }  
        return null;  
    } 
    // 构造方法  
    private Factory(Shape shape, String name) {  
        this.shape = shape;  
        this.name = name;  
    } 
    public String getName() {
        return name;
    }
    public Shape getShape() {
        return shape;
    }


    public void setShape(Shape shape) {
        this.shape = shape;
    }


    public void setName(String name) {
        this.name = name;
    } 
    
}

    1. Summarizing the factory pattern in one sentence.

    • 简单工厂: One factory class, one product abstract class.
    • 工厂方法: Multiple factory classes, one product abstract class.
    • 抽象工厂: Multiple factory classes, multiple product abstract classes.

    2. The factory pattern in everyday life.

    • Simple factory: a McDonald's store can produce multiple kinds of hamburgers.
    • Factory method: a McDonald's store can produce multiple kinds of hamburgers. A KFC store can also produce multiple kinds of hamburgers.
    • Abstract factory: Under Yum! Brands, there are KFC and PepsiCo. KFC produces hamburgers, and PepsiCo produces Pepsi-Cola.

    In the Factory Pattern, we do not expose the creation logic to the client when creating objects, and we use a common interface to point to the newly created object.

    In this exercise, the factory I wrote uses a method (buying a dog) to call the corresponding object creation statements to create different (dog) objects; use the overridden method in the subclass to verify whose method is called after the parent object is assigned.

class Factory{

    The factory pattern helps us encapsulate object creation logic and provides a unified interface for creating different types of objects, making client code more flexible and maintainable. At the same time, the factory pattern also supports extensibility, making it easy to introduce new product types without modifying existing client code.

    The Factory Pattern has many variants, the most common of which are the Simple Factory Pattern, the Factory Method Pattern, and the Abstract Factory Pattern.

    • Simple Factory Pattern: A single concrete factory class is responsible for creating instances of all products. The client requests different types of products by passing different parameters to the factory. The simple factory pattern typically has only one concrete factory class and is suitable for scenarios with fewer objects and relatively simple creation logic.
    • Factory Method Pattern: Defines an abstract method for creating products, and concrete subclass factories implement the process of creating concrete products. Each concrete factory class is responsible for creating one specific product. The Factory Method Pattern can decouple the client from concrete products, allowing the system to introduce new products without modifying client code.
    • Abstract Factory Pattern: Provides an interface for creating a set of related or interdependent product objects. Each concrete factory class is responsible for creating a group of concrete products. The abstract factory pattern can be used to create a family of products rather than just a single product.

    The following is an example of the Simple Factory Pattern:

    // 抽象产品
interface Product {
    void operation();
}

// 具体产品
class ConcreteProductA implements Product {
    public void operation() {
        System.out.println("ConcreteProductA operation");
    }
}

class ConcreteProductB implements Product {
    public void operation() {
        System.out.println("ConcreteProductB operation");
    }
}

// 简单工厂
class SimpleFactory {
    public Product createProduct(String type) {
        if (type.equals("A")) {
            return new ConcreteProductA();
        } else if (type.equals("B")) {
            return new ConcreteProductB();
        }
        return null;
    }
}

// 使用示例
public class Main {
    public static void main(String[] args) {
        SimpleFactory factory = new SimpleFactory();
        Product productA = factory.createProduct("A");
        productA.operation();  // Output: ConcreteProductA operation

        Product productB = factory.createProduct("B");
        productB.operation();  // Output: ConcreteProductB operation
    }
}

    In the example above, we defined the abstract product interface Product and the concrete product classes ConcreteProductA and ConcreteProductB. Through the createProduct method of the simple factory class SimpleFactory, different concrete product instances are created based on the type of parameter passed in.
