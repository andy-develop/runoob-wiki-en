Abstract Factory Pattern

The Abstract Factory Pattern revolves around a super factory that creates other factories. This super factory is also called the factory of other factories. This type of design pattern belongs to the creational patterns, and it provides an optimal way to create objects.

In the abstract factory pattern, the interface is responsible for creating a factory of related objects without explicitly specifying their classes. Each generated factory can provide objects according to the factory pattern.

The abstract factory pattern provides an interface for creating a series of related or interdependent objects without specifying concrete implementation classes. By using the abstract factory pattern, the client can be decoupled from the creation process of concrete products, allowing the client to create a family of products through the factory interface.

概要

意图

Provide an interface for creating a series of related or interdependent objects without specifying their concrete classes.

主要解决

The issue of interface selection.

适用场景

When the system needs to create multiple related or dependent objects without specifying concrete classes.

解决方案

Multiple products are defined within a product family, and concrete factories implement the methods for creating these products.

关键代码

Aggregate the creation methods of multiple similar products in one factory.

应用实例

Suppose there are different types of wardrobes, each wardrobe (concrete factory) can only store one type of clothing (a complete set of concrete products), such as business wear, fashion wear, etc. Each set of clothes includes specific tops and pants (concrete products). All wardrobes are concrete implementations of the wardrobe class (abstract factory), and all tops and pants implement the top interface and pants interface (abstract products) respectively.

优点

  1. Ensure that objects from the same product family work together.
  2. The client does not need to know the concrete class of each object, simplifying the code.

缺点

Extending the product family is very difficult. Adding a new product family requires modifying the code of the abstract factory and all concrete factories.

使用场景

  1. When QQ changes its skin, the entire set of skins is changed together.
  2. When creating cross-platform applications, generate programs for different operating systems.

注意事项

It is relatively easy to add a new product family, but it is more difficult to add a new product hierarchy.

结构

The Abstract Factory Pattern includes the following main roles:

  • Abstract Factory: Declares a set of methods for creating product objects, each method corresponding to a product type. The abstract factory can be an interface or an abstract class.
  • Concrete Factory: Implements the abstract factory interface and is responsible for creating instances of concrete product objects.
  • Abstract Product: Defines a common interface or abstract class for a set of product objects, describing the public methods of the product objects.
  • Concrete Product: Implements the abstract product interface, defining the specific behavior and attributes of the concrete product.

The abstract factory pattern usually involves a family of related products, and each concrete factory class is responsible for creating the concrete products in that family. The client creates product objects by using the abstract factory interface, without directly using the concrete product implementation classes.

    In the example below, the mouse, keyboard, and headset are products, while HP and Dell are factories.

    Simple Factory Pattern

    The Simple Factory Pattern is not one of the 23 patterns. In short, it means having a class dedicated to producing a certain product.

    For example, the mouse factory in the figure below specializes in producing mice. Given parameter 0, it produces a Dell mouse; given parameter 1, it produces an HP mouse.

    工厂模式

    The Factory Pattern means the mouse factory is a parent class with an interface for producing mice.

    The Dell mouse factory and HP mouse factory inherit it, and can produce Dell mice and HP mice respectively.

    The type of mouse to produce is no longer determined by parameters; instead, when creating the mouse factory, it is created by the Dell mouse factory.

    Subsequent direct call鼠标工厂.生产鼠标()即可

    Abstract Factory Pattern

    The Abstract Factory Pattern means not only producing mice, but also producing keyboards.

    That is, the PC manufacturer is a parent class with two interfaces: producing mice and producing keyboards.

    The Dell factory and HP factory inherit it, and can produce Dell mouse + Dell keyboard, and HP mouse + HP keyboard, respectively.

    When creating a factory, it is created by the Dell factory.

    后续工厂.生产鼠标()then it produces a Dell mouse,工厂.生产键盘()then it produces a Dell keyboard.

    In the Abstract Factory Pattern, suppose we need to add a factory.

    Suppose we add an ASUS factory. Then we need to add an ASUS factory that, like the Dell factory, inherits from the PC manufacturer.

    After that, create an ASUS mouse that inherits from the mouse class, and create an ASUS keyboard that inherits from the keyboard class.

    In the Abstract Factory Pattern, suppose we need to add a product.

    Suppose we add the headset product. First, we need to add the headset parent class, and then add the two subclasses: Dell headset and HP headset.

    Then, add an interface for producing headsets to the PC manufacturer parent class. Finally, in the Dell factory and HP factory classes, implement the functionality of producing Dell headsets and HP headsets, respectively. That's all.

    Python 方式：

    # Python原生默认不支持接口，默认多继承，所有的方法都必须不能实现
from abc import  abstractmethod,ABCMeta

# 创建一个接口Shape
class Shape(metaclass=ABCMeta):
    @abstractmethod
    def draw(self):
        pass
#创建Shape的实体类
class Rectangle(Shape):
    def draw(self):
        print("Inside Rectangel:draw() method.")
class Square(Shape):
    def draw(self):
        print("Inside Square:draw() method.")
class Circle(Shape):
    def draw(self):
        print("Inside Circle:draw() method.")

# 创建一个接口Color
class Color(metaclass=ABCMeta):
    @abstractmethod
    def fill(self):
        pass
# 创建Color的实体类
class Red(Color):
    def fill(self):
        print("Inside Red.fill() method.")
class Green(Color):
    def fill(self):
        print("Inside Green.fill() method.")
class Blue(Color):
    def fill(self):
        print("Inside Blue.fill() method.")

#创建抽象工厂
class AbstractFactory(metaclass=ABCMeta):
    @abstractmethod
    def getColor(self,color):
        pass
    @abstractmethod
    def getShape(self,shape):
        pass
#创建抽象工厂实例 ShapeFactory,ColorFactory
class ShapeFactory(AbstractFactory):
    def getShape(self,shapeType):
        if shapeType == None :
            return None
        elif shapeType.upper() == "CIRCLE":
            return Circle()
        elif shapeType.upper() == "RECTANGLE":
            return Rectangle()
        elif shapeType.upper() == "SQUARE":
            return Square()
        return None
    def getColor(self,colorType):
        pass
class ColorFactory(AbstractFactory):
    def getShape(self,shapeType):
        pass
    def getColor(self,colorType):
        if colorType == None:
            return None
        elif colorType.upper() == "RED":
            return Red()
        elif colorType.upper() == "GREEN":
            return Green()
        elif colorType.upper() == "BLUE":
            return Blue()
        return None

# 创建工厂创造器/生产器类
class FactoryProducer():
    @staticmethod
    # 这里不能写成 def getFactory(self,choiceType): 否则会报错
    # 因为是静态方法，被直接调用，所以不能带self参数
    # 如果不是静态方法，必须加self参数，且需要先实例化对象，再用实例化的对象调用方法
    def getFactory(choiceType):
        if choiceType.upper() == "SHAPE":
            return ShapeFactory()
        elif choiceType.upper() == "COLOR":
            return ColorFactory()
        return None

# 调用输出
if __name__ == '__main__':
    shapeFactory = FactoryProducer.getFactory('SHAPE')
    shape1 = shapeFactory.getShape("CIRCLE")
    shape1.draw()
    shape2 = shapeFactory.getShape("RECTANGLE")
    shape2.draw()
    shape3 = shapeFactory.getShape("SQUARE")
    shape3.draw()

    colorFactory = FactoryProducer.getFactory("COLOR")
    color1 = colorFactory.getColor("RED")
    color1.fill()
    color2 = colorFactory.getColor("Green")
    color2.fill()
    color3 = colorFactory.getColor("BLUE")
    color3.fill()

    What is described in this article is actually the Factory Method Pattern, except that an abstract factory class is abstracted from all factory classes. This is not the Abstract Factory Pattern.

    The specific code for the abstract factory pattern is as follows:

    /* 主类 */
public class AbstractFactoryTest {    
    public static void main(String[] args) {        
        System.out.println("=====抽象工厂模式=====");        
        AbstractFactory factory = new Factory1();          
        // 创建工厂1        
        AbstractProductA product = factory.getProductA();  
        // 创建产品A1        
        product.feature();                                 
        // 产品对象的特征方法   
    }
}

/* 抽象产品类A */
abstract class AbstractProductA {    
    abstract public void feature();
}

/* 具体产品类A1 */
class ProductA_one extends AbstractProductA {    
    @Override    
    public void feature() {        
        System.out.println("这是产品A1");    
    }
}

/* 具体产品类A2 */
class ProductA_two extends AbstractProductA {    
    @Override    
    public void feature() {        
        System.out.println("这是产品A2");    
    }
}

/* 抽象产品类B */
abstract class AbstractProductB {    
    abstract public void feature();
}
/* 具体产品类B1 */
class ProductB_one extends AbstractProductB {    
    @Override    
    public void feature() {        
        System.out.println("这是产品B1");    
    }
}
/* 具体产品类B2 */
class ProductB_two extends AbstractProductB {    
    @Override    
    public void feature() {        
        System.out.println("这是产品B2");    
    }
}
/* 抽象工厂类 */
abstract class AbstractFactory {    
    // 创建A族产品    
    abstract public AbstractProductA getProductA();    
    // 创建B族产品    
    abstract public AbstractProductB getProductB();
}
/* 具体工厂类1 */
// 创建不同族，但是属于同一系列的产品（同一后缀名one）
class Factory1 extends AbstractFactory {    
    // 创建产品A1   
     @Override    
     public AbstractProductA getProductA() {        
        return new ProductA_one();    
    }

    @Override    
    public AbstractProductB getProductB() {        
        return new ProductB_one();

    The abstract factory pattern can help us create a family of related product objects, thereby maintaining consistency among products. It can provide a flexible way to create products, decoupling client code from the creation process of concrete products. At the same time, the abstract factory pattern is also extensible, allowing new concrete factories and product types to be easily introduced without modifying existing client code.

    Below is a simple example of the Abstract Factory Pattern. Suppose we have two types of buttons and checkboxes, each with different styles:

    // 抽象产品 - 按钮
interface Button {
    void render();
}

// 具体产品 - MacOS 按钮
class MacOSButton implements Button {
    public void render() {
        System.out.println("Render MacOS button");
    }
}

// 具体产品 - Windows 按钮
class WindowsButton implements Button {
    public void render() {
        System.out.println("Render Windows button");
    }
}

// 抽象产品 - 复选框
interface Checkbox {
    void render();
}

// 具体产品 - MacOS 复选框
class MacOSCheckbox implements Checkbox {
    public void render() {
        System.out.println("Render MacOS checkbox");
    }
}

// 具体产品 - Windows 复选框
class WindowsCheckbox implements Checkbox {
    public void render() {
        System.out.println("Render Windows checkbox");
    }
}

// 抽象工厂
interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// 具体工厂 - MacOS 工厂
class MacOSFactory implements GUIFactory {
    public Button createButton() {
        return new MacOSButton();
    }

    public Checkbox createCheckbox() {
        return new MacOSCheckbox();
    }
}

// 具体工厂 - Windows 工厂
class WindowsFactory implements GUIFactory {
    public Button createButton() {
        return new WindowsButton();
    }

    public Checkbox createCheckbox() {
        return new WindowsCheckbox();
    }
}

// 客户端代码
public class Main {
    public static void main(String[] args) {
        GUIFactory factory = new MacOSFactory();

        Button button = factory.createButton();
        button.render();  // Output: Render MacOS button

        Checkbox checkbox = factory.createCheckbox();
        checkbox.render();  // Output: Render MacOS checkbox
    }
}

    In the above example, we defined the abstract product interfaces Button and Checkbox, as well as the concrete product classes MacOSButton, WindowsButton, MacOSCheckbox, and WindowsCheckbox. Then, we defined the abstract factory interface GUIFactory, and the concrete factory classes MacOSFactory and WindowsFactory. Each concrete factory class is responsible for creating product objects for the corresponding platform.

    By using the abstract factory interface GUIFactory, we can create platform-specific buttons and checkboxes based on client needs, without directly depending on the concrete product implementation classes.
