Git Basic Operations

Git's job is to create and save snapshots of your project and compare them with subsequent snapshots.

This chapter will introduce the commands for creating and committing snapshots of your project.

The 6 commonly used Git commands are:git clone、git push、git add 、git commit、git checkout、git pullWe will introduce this in detail later.

说明：

  • workspace: working directory
  • staging area: staging area/cache area
  • local repository: repository or local repository
  • remote repository：远程仓库

A simple operation step:

$ git init    
$ git add .    
$ git commit
  • git init - Initialize a repository.
  • git add . - Add files to the staging area.
  • git commit - Add the contents of the staging area to the repository.

Git File States

Git file states are divided into three types: Working Directory, Staging Area, and Local Repository. Understanding these concepts and how they interact is the key to mastering Git.

工作目录（Working Directory）

The working directory is the project files you see on your local computer. It is where you actually operate on files, including viewing, editing, deleting, and creating files. All changes to files first occur in the working directory.

Files in the working directory may have the following states:

  • Untracked: A newly created file that has not been recorded by Git.
  • Modified: A file tracked by Git has been modified, but these changes have not yet been committed to Git's records.

暂存区（Staging Area）

The staging area, also called the Index, is a temporary storage area used to hold changes that are about to be committed to the local repository. You can selectively add changes from the working directory to the staging area, so you can commit changes from multiple files at once without having to commit changes from all files.

  • 使用git add <filename>The command adds files from the working directory to the staging area.
  • 使用git add .The command adds all changes in the current directory to the staging area.
git add <filename>  # 添加指定文件到暂存区
git add .           # 添加所有更改到暂存区

本地仓库（Local Repository）

The local repository is a.gitdatabase hidden in the directory, which is used to store all commit history of the project. Each time you commit changes, Git saves the contents of the staging area into the local repository.

使用git commit -m "commit message"The command commits changes in the staging area to the local repository.

git commit -m "commit message"  # 提交暂存区的更改到本地仓库

File State Transition Process

Untracked: Newly created files are initially untracked. They exist in the working directory but are not tracked by Git.

touch newfile.txt  # 创建一个新文件
git status         # 查看状态，显示 newfile.txt 未跟踪

Tracked： 通过git addAfter the command adds an untracked file to the staging area, the file becomes tracked.

git add newfile.txt  # 添加文件到暂存区
git status           # 查看状态，显示 newfile.txt 在暂存区

Modified: After making changes to a tracked file, these changes are shown as modified, but these changes have not yet been added to the staging area.

echo "Hello, World!" > newfile.txt  # 修改文件
git status                          # 查看状态，显示 newfile.txt 已修改

Staged： 使用git addAfter the command adds modified files to the staging area, the files enter the staged state, waiting to be committed.

git add newfile.txt  # 添加文件到暂存区
git status           # 查看状态，显示 newfile.txt 已暂存

Committed： 使用git commitAfter the command commits the changes in the staging area to the local repository, these changes are recorded, and the file status returns to tracked.

git commit -m "Added newfile.txt"  # 提交更改
git status                         # 查看状态，工作目录干净

    git commit、git push、git pull、 git fetch、git merge 的含义与区别

    • git commit: It commits locally modified files to the local repository;
    • git push: sends the latest information in the local repository to the remote repository;
    • git pull: fetches the latest version from the remote to the local and automatically merges;
    • git fetch: fetches the latest version from the remote to the local and does not automatically merge;
    • git merge: It is used to merge from the specified commit(s) into the current branch, to merge two branches;
    $ git merge -b  // 指将 b 分支合并到当前分支

    git pull相当于git fetch + git merge。

    Summary of points to note in Git basic operations:

    git clone <source repository> <destination repository>

    The command method to clone a local repository.

    <source repository>: the path of the local repository you want to clone

    <destination repository>: the path where you want to clone to another location. For example, git clone d:/git e:/git11 clones the repository at d:/git (i.e., the directory containing the hidden file .git) to the e:/git11 directory.

    注意：

    1、<destination repository>The directory must not have been created in the file system, or if it has been created, it must be empty; otherwise, cloning will not succeed.

    2. Unlike pulling a repository from a remote, there is no need to write the last part of the path..gitto indicate that this is a repository.

    git status –s

    Obtain a brief status output.

    git diff
    • git diff: View the differences between the working directory and the staging area.
    • git diff –cached [<commit>]: View the differences between the staging area and the specified commit version; the version can be omitted (defaults to HEAD).
    • git diff <commit>: View the differences between the working directory and the specified commit version.
    • git diff <commit>..<commit>: View the differences between two specified commit versions, either of which can be omitted (defaults to HEAD).
    • git diff <commit>...<commit>: View the differences between the specified commit versions of two different branches; either may be omitted (defaults to HEAD). This command is equivalent to git diff $(git-merge-base A B) B.
    git commit –am ""

    Directly commit all modifications, equivalent to running add and commit together.

    Note: All files must be tracked; if you have created a new file that is untracked, this command will not be executed.

    git checkout

    Unlike git reset, reset replaces the entire directory tree, and redundant files will be deleted. Checkout only replaces the specified files and leaves redundant files untouched.

    git rm

    Delete files from the working directory and the staging area. Use --cached to delete only from the staging area. Use -rf <directory> to delete all files and subdirectories under the specified directory.

    git mv <source> <destination>

    Move or rename in the working directory and the staging area. If <destination> is not a directory name, a rename is performed. If it is a directory name, a move is performed.
