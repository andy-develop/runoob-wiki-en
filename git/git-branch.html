Git Branch Management

Git branch management is one of Git's powerful features that allows multiple developers to work in parallel, develop new features, fix bugs, or run experiments without affecting the main codebase.

Almost every version control system supports branches in some form; a branch represents an independent line of development.

Using branches means you can separate from the main development line and continue working without affecting the main line.

Git branches are actually pointers to change snapshots.

Some people call Git's branching model必杀技特性, and precisely because of it,Gitdistinguishing it from the family of version control systems.

创建分支

Create a new branch and switch to it:

git checkout -b <branchname>

例如：

git checkout -b feature-xyz

Switch branch command:

git checkout (branchname)

例如：

git checkout main

When you switch branches, Git replaces the contents of your working directory with the snapshot of the last commit on that branch, so multiple branches do not require multiple directories.

查看分支

View all branches:

git branch

View remote branches:

git branch -r

View all local and remote branches:

git branch -a

合并分支

Merge other branches into the current branch:

git merge <branchname>

For example, switch to the main branch and merge the feature-xyz branch:

git checkout main
git merge feature-xyz

Resolve merge conflicts

When a conflict occurs during a merge, Git marks the conflicting files, and you need to resolve the conflict manually.

Open the conflicted file and resolve the conflict according to the markers.

Mark conflict resolution as complete:

git add <conflict-file>

Commit the merge result:

git commit

删除分支

Delete local branch:

git branch -d <branchname>

Forcefully delete an unmerged branch:

git branch -D <branchname>

Delete remote branch:

git push origin --delete <branchname>

Git Branch Management

列出分支

Basic commands for listing branches:

git branch

Without arguments,git branchThis will list the branches in your local repository.

$ git branch
* master

This example means that we have one calledmasterbranch, and that branch is the current branch.

当你执行git initBy default, Git will create for you whenmaster分支。

If we want to manually create a branch, rungit branch (branchname)即可。

$ git branch testing
$ git branch
* master
  testing

Now we can see that there is a new branchtesting。

When you create a new branch this way after the last commit, if there are later commits, and then you switch to thetestingbranch, Git will restore your working directory to what it was when you created the branch.

Next, we will demonstrate how to switch branches. We use git checkout (branch) to switch to the branch we want to modify.

$ ls
README
$ echo 'runoob.com' > test.txt
$ git add .
$ git commit -m 'add test.txt'
[master 3e92c19] add test.txt
 1 file changed, 1 insertion(+)
 create mode 100644 test.txt
$ ls
README        test.txt
$ git checkout testing
Switched to branch 'testing'
$ ls
README

When we switch totestingbranch, the new file test.txt we added was removed. Switch back tomasterWhen branching, they reappear.

$ git checkout master
Switched to branch 'master'
$ ls
README        test.txt

We can also use the git checkout -b (branchname) command to create a new branch and immediately switch to it, allowing us to work within that branch.

$ git checkout -b newtest
Switched to a new branch 'newtest'
$ git rm test.txt 
rm 'test.txt'
$ ls
README
$ touch runoob.php
$ git add .
$ git commit -am 'removed test.txt、add runoob.php'
[newtest c1501a2] removed test.txt、add runoob.php
 2 files changed, 1 deletion(-)
 create mode 100644 runoob.php
 delete mode 100644 test.txt
$ ls
README        runoob.php
$ git checkout master
Switched to branch 'master'
$ ls
README        test.txt

As you can see, we created a branch, removed the file test.txt on that branch, and added the runoob.php file, then switched back to our main branch. The deleted test.txt file returned, and the newly added runoob.php does not exist in the main branch.

Using branches to separate work allows us to work in different development environments and switch back and forth.

删除分支

Delete branch command:

git branch -d (branchname)

For example, if we want to delete the testing branch:

$ git branch
* master
  testing
$ git branch -d testing
Deleted branch testing (was 85fc7e7).
$ git branch
* master

分支合并

Once a branch has independent content, you will eventually want to merge it back into your main branch. You can use the following command to merge any branch into the current branch:

git merge
$ git branch
* master
  newtest
$ ls
README        test.txt
$ git merge newtest
Updating 3e92c19..c1501a2
Fast-forward
 runoob.php | 0
 test.txt   | 1 -
 2 files changed, 1 deletion(-)
 create mode 100644 runoob.php
 delete mode 100644 test.txt
$ ls
README        runoob.php

In the example above, we merged the newtest branch into the main branch, and the test.txt file was deleted.

After merging, you can delete the branch:

$ git branch -d newtest
Deleted branch newtest (was c1501a2).

After deletion, only the master branch remains:

$ git branch
* master

合并冲突

Merging is not just a simple operation of adding or removing files; Git also merges modifications.

$ git branch
* master
$ cat runoob.php

注意：If runoob.php does not exist, you need to create this file first. The command can betouch runoob.php。

First, we create a branch called change_site, switch to it, and change the content of runoob.php to:

<?php

?>

Create the change_site branch:

$ git checkout -b change_site

$ vim runoob.php
$ head -3 runoob.php

?>
$ git commit -am 'changed the runoob.php'
[change_site 7774248] changed the runoob.php

Commit the modified content to the change_site branch. Now, if we switch back to the master branch, we can see the content restored to what it was before our modification (empty file, no code). We modify the runoob.php file again.

    分支工作流

    Git Flow is a commonly used branching workflow, divided into the following branch types:

    • 主分支（main/master）: Store production code.
    • Development branch (develop): Store code about to be released.
    • Feature branch (feature)：从developBranch created for developing new features.
    • Release branch (release)：从developBranch created for preparing releases.
    • Hotfix branch (hotfix)：从mainBranch creation, used for urgent fixes to production issues.

    Create a feature branch:

    git checkout develop
git checkout -b feature/xyz

    Complete feature development and merge:

    git checkout develop
git merge feature/xyz
git branch -d feature/xyz

    Create a release branch:

    git checkout develop
git checkout -b release/1.0.0

    Release and merge into the main branch and development branch:

    git checkout main
git merge release/1.0.0
git tag -a 1.0.0 -m "Release 1.0.0"
git checkout develop
git merge release/1.0.0
git branch -d release/1.0.0

    Create a hotfix branch:

    git checkout main
git checkout -b hotfix/1.0.1

    Complete the fix and merge:

    git checkout main
git merge hotfix/1.0.1
git tag -a 1.0.1 -m "Hotfix 1.0.1"
git checkout develop
git merge hotfix/1.0.1
git branch -d hotfix/1.0.1

    实例

    The following is a comprehensive example demonstrating branch creation, switching, merging, and deletion.

    Create and switch branches:

    git checkout -b feature-abc

    Develop and commit changes:

    # 编辑文件并提交
git add .
git commit -m "Develop feature ABC"

    Merge to the main branch:

    git checkout main
git merge feature-abc

    Delete local branch:

    git branch -d feature-abc
