MongoDB Limit and Skip Methods

MongoDB Limit() Method

If you need to read a specified number of data records in MongoDB, you can use MongoDB's limit() method. If you want to skip a specified number of documents and read data, you can use the skip() method.

The limit() method is used to limit the number of documents returned by a query, while the skip() method is used to skip a specified number of documents. These two methods are often used together to implement pagination queries or batch processing on large datasets.

limit() Method

The limit() method is used to limit the number of documents returned by a query.

Syntax

The basic syntax of the limit() method is as follows:

db.collection.find().limit(<limit>)
  • <limit>: The number of documents to return.

Example

// Return the first 10 documents
db.myCollection.find().limit(10);

skip() Method

In addition to using the limit() method to read a specified number of data records, we can also use the skip() method to skip a specified number of data records. The skip() method also accepts a numeric parameter as the number of records to skip.

The skip() method is used to skip a specified number of documents, thereby enabling pagination or batch queries.

Syntax

The syntax format of the skip() method is as follows:

db.collection.find().skip(<skip>)
  • <skip>: The number of documents to skip.

Example

// Skip the first 10 documents and return the next 10 documents
db.myCollection.find().skip(10).limit(10);

Example

The following example will only display the second document data

>db.col.find({},{"title":1,_id:0}).limit(1).skip(1)
{ "title" : "Java 教程" }
>

Pagination query:

Example

// First page, 10 documents per page
db.myCollection.find().skip(0).limit(10);

// Second page, 10 documents per page
db.myCollection.find().skip(10).limit(10);

// Third page, 10 documents per page
db.myCollection.find().skip(20).limit(10);

Note:The default parameter of the skip() method is 0.

Notes

  • skip() 和 limit()The methods are usually used together to implement pagination queries. However, using them on large datasetsskip()may cause performance issues, because MongoDB needs to scan and skip the specified number of documents when executing the query, so it is recommended to use them only when necessaryskip()method, and try to avoid continuous use on large datasets.
  • When combinedskip() 和 limit(),skip()should belimit()used before, to avoid unexpected behavior.

By usinglimit() 和 skip()method, you can implement pagination of query results in MongoDB, improving query flexibility and performance.

    Supplementary note: the skip and limit methods are only suitable for pagination with small data volumes. If the data volume is in the millions, the efficiency will be very low, because the skip method counts data one by one. It is recommended to use where_limit

    After looking at some materials, I found that all of them say the same thing:

    Do not easily use Skip to perform queries, otherwise when the data volume grows, performance will drop sharply. This is because Skip counts one by one, so when there are many records, it naturally becomes slow.

    So it seems Skip should be avoided. Then how to avoid it? First, let's review the latter timestamp pagination scheme in SQL pagination. This approach leverages the ordered nature of fields and uses queries to fetch data, which can directly avoid a large amount of counting. In other words, if we can attach such a condition, query efficiency will improve. Is that really the case? Let's verify:

    Here, let's assume we want to query the 100001st record, and the Amount value of this record is 2399927. Let's write two statements as follows:

    b.test.sort({"amount":1}).skip(100000).limit(10)  //183ms
db.test.find({amount:{$gt:2399927}}).sort({"amount":1}).limit(10)  //53ms

    The results have been attached in the comments. Obviously, the performance of the latter is one-third of the former, and the gap is very large. This also confirms the theory that Skip has poor efficiency.

    limit(n) is used to specify the number of records to display, while skip(n) is used to skip a number of records starting from the first record among the matching records. These two functions can be used interchangeably.

    For example: find({},{age:1,_id:0}).limit(2).skip(1), among the matching documents, two documents are to be displayed, and the display starts after skipping the first record. This is not easy to understand.

    If it is written as find({},{age:1,_id:0}).skip(1).limit(2), among the matching documents, first skip the first document, then display two documents. This is easier to understand.
