JavaScript Hoisting

In JavaScript, declarations of functions and variables are hoisted to the top of the function.

In JavaScript, a variable can be declared after it has been used; in other words, a variable can be used before it is declared.

The following two examples will get the same result:

Example 1

x = 5; // Set variable x to 5
elem = document.getElementById("demo"); // Find the element
 elem.innerHTML = x;                     // Display x in the element

var x; // Declare x

Try it Yourself »

Example 2

var x; // Declare x
 x = 5; // Set variable x to 5

elem = document.getElementById("demo"); // Find the element
elem.innerHTML = x;                     // Display x in the element

Try it Yourself »

To understand the above examples, you need to understand "hoisting".

Hoisting: Function declarations and variable declarations are always silently "hoisted" to the very top of the method body by the interpreter.

JavaScript Initializations Are Not Hoisted

JavaScript initializations are not hoisted. In JavaScript, only the variable declarations are hoisted, not the initializations.

The following two examples do not get the same result:

Example 1

var x = 5; // Initialize x
var y = 7; // Initialize y

elem = document.getElementById("demo"); // Find the element
 elem.innerHTML = x + " " + y;           // Display x and y

Try it Yourself »

Example 2

var x = 5; // Initialize x
elem = document.getElementById("demo"); // Find the element
 elem.innerHTML = x + " " + y;           // Display x and y
var y = 7; // Initialize y

Try it Yourself »

In Example 2, y outputs undefined,undefinedThis is because the variable declaration (var y) is hoisted, but the initialization (y = 7) is not hoisted, so the y variable is an undefined variable.

Example 2 behaves like the following code:

var x = 5; // 初始化 x
var y;     // 声明 y

elem = document.getElementById("demo"); // 查找元素
elem.innerHTML = x + " " + y;           // 显示 x 和 y

y = 7;    // 设置 y 为 7

Declare Your Variables at the Top!

Most programmers do not know about JavaScript hoisting.

If programmers do not have a good understanding of hoisting, the programs they write are prone to errors.

To avoid these problems, we usually declare these variables at the beginning of each scope. This is also the normal JavaScript parsing step, making it easier to understand.

JavaScript strict mode does not allow undeclared variables to be used.
In the next chapter, we will learn about"strict mode" 。

    Actually, you mainly just need to understand JS's parsing mechanism.

    When encountering a script tag, JS performs pre-parsing, hoisting variable (var) and function declarations, but does not execute the function. Then it enters context execution. Context execution still performs the same pre-parsing operation until there are no more var and function declarations, and then it starts executing the context. For example:

    a=5;
show();
var a;
function show(){};

    Pre-parsing:

    function show(){};
var a;
a=5;
show();

    It should be noted that function declaration hoisting directly lifts the entire function to the very top of the execution environment.

    In addition to the function declaration method above, you can also use anonymous functions.

    Declaration:

    var 变量名称=function(形参列表){
  //函数体
}

    Call:

    Variable name (actual argument list)

    Note: With anonymous functions, there is no function hoisting, because the function name is represented by a variable, so only variable hoisting exists. Example:

    var getName=function(){
  console.log(2);
}

function getName(){
  console.log(1);
}

getName();
//结果为2

    Some people may think the final output is 1. But getName is a variable, so the declaration of this variable is also hoisted to the top, while the assignment to the variable remains in its original position. Note that functions take precedence. Although both function declarations and variable declarations are hoisted, functions are hoisted first, and then variables.

    //函数、变量声明提升后
function getName(){    //函数声明提升到顶部
  console.log(1);
}

var getName;    //变量声明提升
getName = function(){    //变量赋值依然保留在原来的位置
  console.log(2);
}

getName();    // 最终输出：2

    First, JS has a precompilation process before execution. Variable hoisting and function hoisting happen here.

    When executing the jsFun6 function, it first creates an AO object (Activetion Object, execution context).

    AO{

}

    Then it will use the formal parameters and variable declarations as property names of the AO object, with property values set to undefined.

    We can see that the jsFun6 function has no formal parameters, but has the following variable declarations:

    第10行的 var test2
第15行的 var test3
第19行的 var test4
第27行的 var test5

    So the AO object now looks like this:

    AO{
    test2：undefined
    test3：undefined
    test4：undefined
    test5：undefined
}

    Then it will pass the values of the actual parameters to the formal parameters (currently there are no formal parameters, so this step is skipped).

    Then it finds function declarations and uses them as property names of the AO object, with property values being the function body of the function declaration (this is function declaration hoisting).

    We can see that the jsFun6 function has the following function declarations:

    第4行 function test1(){}
第22行 function test4(){}

    Lines 10 and 15 here are function expressions, not function declarations.

    So the AO object now looks like this:

    AO{
    test2：undefined,
    test3：undefined,
    test4：function test4(){alert("测试4");},
    test5：undefined,
    test1：function test1(){alert("测试1");}
}

    Note that because the AO object already had a test4 property, the test4 property originally obtained from the variable declaration is overwritten by the test4 from the function declaration.

    At this point precompilation is complete and execution begins.

    During execution, it first looks in the AO object. If not found, it looks in the GO (Global Object) object. (The AO object is equivalent to local variables, and the GO object is equivalent to global variables.)

    When executing line 3, test1 is found in AO and executed, and a dialog box pops up showing the message "Test 1".

    Line 4 has already been hoisted, so it can be skipped. Other similar lines below are the same.

    When executing line 8, test2 is found in AO and run as a function. Since the value of test2 in AO is undefined, execution will throw an error.

    AO{
    test2：function(){alert("测试2");},
    test3：undefined,
    test4：function test4(){alert("测试4");},
    test5：undefined,
    test1：function test1(){alert("测试1");}
}

    What is variable hoisting?

    In principle, variables should be declared before use, but novice programmers often use variables without declaring them. When this happens, the JS code does not throw an error during execution; it simply returns undefined. This situation is variable hoisting.

    When the computer executes, it implicitly places variables that are used without declaration at the very top of the code. Note that although the variable is hoisted, the value assigned to the variable is not hoisted along with it, so the result is undefined.

    What is function hoisting?

    It is similar to variable hoisting: using a function first and declaring it later. This illogical thing is allowed in JavaScript; the language is just that flexible.

    Unlike variable hoisting, the function's return value is also hoisted along with it, so you will find that you can call the function anywhere within the `<script>` tag and use its return value.
