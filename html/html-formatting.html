Formatting Tags

HTML Using tags <b>("bold") and <i>("italic") to format output text, as shown:Bold or Italic

These HTML tags are called formatting tags (please refer to the complete tag reference manual at the bottom).

Typically, the <strong> tags replace the <b> tags for use, and <em> tags replace <i> tags.

However, the meanings of these tags are different:

<b> and <i> define bold or italic text.

<strong> or <em> indicate text that is important and should be highlighted. Modern major browsers can render various effects on fonts. However, future browsers may support better rendering effects.

    About <b> and <strong>

    In terms of display, these two tags can both be bold text, so why are there two functions "the same" tags? And it seems that strong is not an exception.

    • First, these are not completely identical. For example, if you read a webpage using a web browser (blind people), the strong tag will be read, but the b tag will not.
    • Second, from a historical perspective, strong was born to build a semantic web. It is known that HTML is responsible for displaying, not for indicating the meaning of the tag. That is to say, the browser knows how to display the tag, but it does not know what the meaning of the tag should be. So strong is the first step in the semantic direction.

    <acronym>Tags and<abbr>Tags have been used in HTML to represent abbreviations or initialisms in the past, but there are some differences between them, especially in modern HTML standards and browser support:

    1. Semantic meaning:

      • <abbr>Tags are used to denote any type of abbreviation or acronym, whether it consists of a part of a word or a read-only single-word acronym that can be read as a whole (e.g., "VIP", "CEO"), or a read-only single-word acronym that can be read as a whole (e.g., "UNESCO", "NASA").
      • <acronym>Tags were originally designed to denote read-only single-word acronyms that can be read as a whole (e.g., "ASCII", "FAQ"), but are now used to denote any type of abbreviation or acronym, whether it consists of a part of a word or a read-only single-word acronym that can be read as a whole.

    2. Browser support and current status:

      • <abbr>Tags are well-supported in all modern browsers and are part of the HTML5 standard.
      • <acronym>Tags were originally defined in HTML 4.01 but have been deprecated in HTML5 and are no longer recommended for use. This means that while some older browsers may still support it, modern browsers may no longer guarantee compatibility with it, and using it may result in code that does not conform to the latest standards.

    3. Replacement suggestion:

      • Since<acronym>Tags should be replaced with<abbr>Tags to denote any type of abbreviation or acronym. This ensures standardization of the code and consistent browser support.
      • For situations where a full term or phrase is needed, regardless of which tag is used, thetitleattribute should be used to provide a complete term or phrase, so that users can see a tooltip when hovering over the tag.

    In summary, although<acronym> 和 <abbr>Tags have a slight semantic difference, in practical applications, since<acronym>has been deprecated in HTML5, developers should always use<abbr>Tags to mark all types of abbreviations, regardless of whether they are read-only single-word acronyms. This ensures compliance with the current standards and ensures cross-browser compatibility.

    The <cite> tag can also be used to annotate citations when citing references in a block quote.

    The <cite> tag and <footer> tag have different applicable scenarios and semantic meanings when used to denote citations. The choice of which tag to use depends on the specific content and context of the annotation.

    <cite>Tags:

    • Usage:<cite>Tags are used to denote the title of works (such as articles, books, songs, films, patents, legal cases, etc.), or the names of individuals or organizations mentioned in the context of references, quotations, or comments.
    • Semantic: Denotes a formal citation or mention of a work or creator, emphasizing respect and recognition of the original source.
    • Applicable scenarios: When referring to others' opinions or viewpoints in articles, blogs, forum posts, etc., typically use<cite>to mark the source of the author, title of the work, publication date, etc., to provide information about the source and attribution.

    <footer>Tags:

    • Usage:<footer>Tags are used to define the footer content of a document or page, typically containing copyright information, contact information, usage terms, author attribution, and creation date, among other important but non-core content.
    • Semantic: Denotes the bottom area of a document or page, containing a series of additional information and services, rather than just attribution.
    • Applicable scenarios: Used to summarize and present all the information related to the owner, creator, publisher, and revision date, as well as possible navigation links, legal statements, contact information, etc., on web pages, e-books, documents, etc.

    Selection of citation:

    • For the author or contributor of specific content units, such as articles, blogs, forum posts, etc., if the citation is to indicate the author or contributor, it is usually more appropriate to use<footer>Tags. In this case, the citation is part of the content block and together with copyright information, creation date, etc., forms a complete description and attribution of the content.

    • For the citation of others' works, i.e., indicating the author, source, etc., of the cited work, it should use<cite>Tags. In this case, the citation is an annotation of the cited work, with the purpose of giving the source and respect for the original author.
