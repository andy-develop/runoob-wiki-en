Linux kill command

Linux Command Encyclopedia

The Linux kill command is used to terminate running processes.

The kill command can send different signals to the target process to perform different operations. If no signal is specified, it sends the TERM signal (15) by default, which terminates the process. If the program still cannot be terminated, you can use the SIGKILL (9) signal to attempt to forcefully kill the program.

Syntax

kill [options] <PID>

<PID> is the process ID of the process to be terminated.

Parameter description：

  • -l: List all available signals.
  • -<signal>: Send a specific signal to the target process, for example-9means sending the KILL signal, i.e., forcefully terminating the process.

Basic Usage

Terminate a process:By default, the kill command sends SIGTERM (signal 15), which requests process termination. If the process does not catch this signal, it will be terminated.

kill PID

Where PID is the process ID.

Send a specific signal:Via-sthe option, you can send a specified signal.

kill -s SIGNAL PID

For example, sending SIGKILL (signal 9) will immediately terminate the process; it cannot be ignored or caught.

kill -9 PID

Kill a process group:Use the -9 option to kill the entire process group.

kill -9 -PID

Use the kill -l command to list all available signals.

The most commonly used signals are:

  • SIGKILL(Signal 9): Immediately ends the process; cannot be caught or ignored.
  • SIGTERM(Signal 15): Ends the process normally; can be caught or ignored.
  • SIGSTOP(Signal 19): Suspends the process; cannot be caught, ignored, or ended.
  • SIGCONT(Signal 18): Continues executing a suspended process.
  • SIGINT(Signal 2): Usually the signal produced by Ctrl+C; it can be caught or ignored by the process.

Examples

Terminate the process with PID 1234:

kill 1234

Forcefully terminate the process with PID 1234:

kill -9 1234

Send SIGSTOP to the process with PID 1234:

kill -s SIGSTOP 1234

Notes

  • When usingkillthe command, you need to have appropriate permissions; otherwise, you may not be able to terminate the process.
  • Some processes may require multiple signals to be sent before they terminate, such as certain daemon processes.
  • Forcefully killing a process may cause data loss or other side effects, so use it with caution.

    To correct the above comment:

    1. kill -9 forcefully terminates a process; under normal circumstances, the process cannot decide whether to exit. If kill -9 cannot terminate it, it means: 1) the process is a zombie process; 2) the process is in "kernel mode".
    2. kill without arguments defaults to kill -15, which means ending the process normally. The process can receive this signal to release resources or save state; it is commonly used for graceful shutdown.
