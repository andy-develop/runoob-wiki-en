Linux Disk Management

The quality of Linux disk management directly affects the performance of the entire system.

The three commonly used commands for Linux disk management are:df、du 和 fdisk。

  • df(English full name: disk free): Lists the overall disk usage of the file system
  • du(English full name: disk used): Checks disk space usage
  • fdisk: Used for disk partitioning

df

The df command parameter function: Checks the disk space usage of the file system. You can use this command to obtain information such as how much space on the hard drive is occupied and how much space is currently remaining.

Syntax:

df [-ahikHTm] [目录或文件名]

Options and parameters:

  • -h: Displays output results in a human-readable format (e.g., using units such as KB, MB, GB).

  • -T: Displays the file system type.

  • -t <文件系统类型>: Only displays file systems of the specified type.

  • -i: Displays inode usage.

  • -H: This parameter is-ha variant of it, but uses 1000 bytes as the base unit instead of 1024 bytes. This means it displays disk usage in SI (International System of Units) units (such as MB, GB) rather than binary units (such as MiB, GiB).

  • -k: This option displays disk space usage in KB as the unit.

  • -a: This parameter displays all file systems, including virtual file systems, such asproc、sysfsetc. If this option is not used, by default,dfthe command will not display virtual file systems.

Example 1

List all file systems on the system!

[root@www ~]# df
Filesystem      1K-blocks      Used Available Use% Mounted on
/dev/hdc2         9920624   3823112   5585444  41% /
/dev/hdc3         4956316    141376   4559108   4% /home
/dev/hdc1          101086     11126     84741  12% /boot
tmpfs              371332         0    371332   0% /dev/shm

In Linux, if df is used without any options, by default it will list all file systems in the system (excluding special in-memory file systems and swap) with a capacity of 1 Kbytes!

Example 2

Display the capacity results in a readable capacity format

[root@www ~]# df -h
Filesystem            Size  Used Avail Use% Mounted on

du

The Linux du command is also used to view used space, but unlike the df command, the Linux du command checks the disk space used by files and directories. It still has some differences from the df command. Here we introduce the Linux du command.

Syntax:

du [-ahskm] 文件或目录名称

Options and parameters:

  • -a: Lists the capacity of all files and directories, because by default only the file amounts under directories are counted.
  • -h: Displays in a more human-readable capacity format (G/M);
  • -s: Only displays the total size of the specified directory or file, without showing the sizes of its subdirectories.
  • -S: Includes the total of subdirectories, which is somewhat different from -s.
  • -k: Lists capacity in KBytes;
  • -m: Lists capacity in MBytes;

Example 1

Only list the capacity of all folders in the current directory (including hidden folders):

[root@www ~]# du
8       ./test4     <==每个目录都会列出来
8       ./test2
....中间省略....
12      ./.gconfd   <==包括隐藏文件的目录
220     .           <==这个目录(.)所占用的总量

When du is entered directly without any options, du will analyze the hard disk space occupied by subdirectories in the current directory.

Example 2

Also list the capacity of files

[root@www ~]# du -a
12      ./install.log.syslog   <==有文件的列表了
8       ./.bash_logout
8       ./test4
8       ./test2
....中间省略....
12      ./.gconfd
220     .

Example 3

Check the capacity occupied by each directory under the root directory

[root@www ~]# du -sm /*
7       /bin
6       /boot
.....中间省略....
0       /proc
.....中间省略....
1       /tmp
3859    /usr     <==系统初期最大就是他了啦！
77      /var

The wildcard * is used to represent each directory.

Unlike df, the du command actually goes directly into the file system to search for all file data.

Disk Formatting

After disk partitioning is complete, the natural next step is to format the file system. The formatting command is very simple; use themkfs(make filesystem) command.

Syntax:

mkfs [-t 文件系统格式] 装置文件名

Options and parameters:

  • -t: Can take a file system format, such as ext3, ext2, vfat, etc. (It only takes effect if the system supports it)

Example 1

View the file formats supported by mkfs

[root@www ~]# mkfs[tab][tab]
mkfs         mkfs.cramfs  mkfs.ext2    mkfs.ext3    mkfs.msdos   mkfs.vfat

Press [tab] twice, and you will find that the file formats supported by mkfs are as shown above.

Example 2

Format the partition /dev/hdc6 (you can specify your own partition) as an ext3 file system:

[root@www ~]# mkfs -t ext3 /dev/hdc6

Disk Check

fsck (file system check) is used to check and maintain inconsistent file systems.

If the system loses power or the disk has problems, the fsck command can be used to check the file system.

Syntax:

fsck [-t 文件系统] [-ACay] 装置名称

Options and parameters:

  • -t: Specifies the type of the file system. If it is already defined in /etc/fstab or is already supported by the kernel itself, this parameter does not need to be added.
  • -s: Executes fsck commands one by one in sequence to check.
  • -A: Checks all partitions listed in /etc/fstab.
  • -C: Displays the complete check progress.
  • -d: Prints the debug results of e2fsck.
  • -p: When combined with the -A condition, multiple fsck checks are executed together at the same time.
  • -R: When combined with the -A condition, omits / and does not check it.
  • -V: Verbose display mode.
  • -a: Automatically repairs if errors are found during the check.
  • -r: If errors are found during the check, the user is asked whether to repair them.
  • -y: The option specifies that yes is automatically input for checking each file. When you are not sure which files are abnormal, you can execute # fsck -y to check and repair everything.

Example 1

View how many file system fsck commands are supported by the system:

[root@www ~]# fsck[tab][tab]
fsck         fsck.cramfs  fsck.ext2    fsck.ext3    fsck.msdos   fsck.vfat

Example 2

Forcefully check the /dev/hdc6 partition:

[root@www ~]# fsck -C -f -t ext3 /dev/hdc6 
fsck 1.39 (29-May-2006)
e2fsck 1.39 (29-May-2006)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
vbird_logical: 11/251968 files (9.1% non-contiguous), 36926/1004046 blocks

If the -f option is not added, since this file system has never had problems, the check process will be very fast! Only if -f is added for a forced check will the process be displayed item by item.

Disk Mounting and Unmounting

Linux disk mounting uses themountcommand, and unmounting uses theumountcommand.

Disk mounting syntax:

mount [-t 文件系统] [-L Label名] [-o 额外选项] [-n]  装置文件名  挂载点

Example 1

Use the default method to mount the just-created /dev/hdc6 to /mnt/hdc6!

[root@www ~]# mkdir /mnt/hdc6
[root@www ~]# mount /dev/hdc6 /mnt/hdc6
[root@www ~]# df
Filesystem           1K-blocks      Used Available Use% Mounted on
.....中间省略.....
/dev/hdc6              1976312     42072   1833836   3% /mnt/hdc6

Disk unmount commandumountSyntax:

umount [-fn] 装置文件名或挂载点

Options and parameters:

  • -f: Force unmount! Can be used in situations such as when a network file system (NFS) cannot be read;
  • -n: Unmount without updating /etc/mtab.

Unmount /dev/hdc6

[root@www ~]# umount /dev/hdc6

    In the Linux operating system, file data usually contains many attributes in addition to the actual file content, such as Linux file permissions (rwx) and file attributes (owner, group, time parameters, etc.). The file system typically stores these two parts of data in separate blocks: permissions and attributes are stored in the inode, while the actual data is placed in the data block. In addition, there is a superblock that records the overall information of the entire file system, including the total, used, and remaining amounts of inodes and blocks.

    inode: Records the attributes of a file. Each file occupies one inode, which also records the block where the file's data is located.

    In Linux, you can use the stat command to view the inode information of a file:

    stat /etc/passwd
    linux-peanut:~/Desktop # stat /etc/passwd

  Size: 2269          Blocks: 8          IO Block: 4096   regular file

    The author explained it very well, but unfortunately there are some issues with the specific operations (not detailed enough) and mounting was not well explained. When mounting on Linux running on a virtual machine, you first need to add a hard disk, then format it, create partitions on it, create a directory, and only then mount it.

    I came across a fairly good article explaining mounting:

    The role of mounting had never been very clear to me. Today, while reading a textbook, I came across the mount command and found that its use is obscure but very powerful. Unfortunately, the textbook wasn't clear, so I gathered some excellent explanations online, and after reading them, everything became clear.

    • 1. To mention one thing: under Windows, mount mounting is simply providing a drive letter (C, D, E, ...) for a disk partition. For example, when a USB flash drive is inserted, the system automatically assigns it the I: drive letter—this is actually mounting. When you safely eject the USB drive before removing it, that is actually unmounting.
    • 2. Under Linux, unlike Windows which can have multiple directories like C, D, E, Linux has only one root directory /. When installing the system, all the partitions we allocate to Linux are located somewhere under /, such as /home, etc.
    • 3. The questioner inserted a new hard disk and partitioned a new disk area sdb1. It does not yet belong to /.
    • 4. Although we can find its location in some graphical desktop systems and browse and manage the files inside, on the command line we don't know how to access its directory—for example, we cannot use cd or ls. Nor can we specify a directory in programming to operate on it.
    • 5. At this point, the questioner used mount /dev/sdb1 ~/Share/ to mount the sdb1 partition of the new hard disk to the ~/Share/ folder in the working directory. After that, accessing this ~/Share/ folder is equivalent to accessing the sdb1 partition of hard disk 2. Any operation on /Share/ is equivalent to an operation on the files in sdb1.
    • 6. Therefore, under Linux, the function of mount is to attach a device (usually a storage device) to an existing directory. Accessing this directory means accessing the storage device.
    • 7. The Linux operating system treats all devices as files, integrating the entire computer's resources into one large file directory. To access files on a storage device, we must mount the partition where the files are located to an existing directory, and then access the storage device through that directory. Mounting is the process of placing a device under a directory so that the system knows how to manage the files on the device and understands characteristics such as the read/write properties of the storage device.
    • 8. Don't we have /dev/sdb1? Can't we just operate on it directly? Isn't it its directory?
    • 9. This is not its directory. Although /dev is a directory, /dev/sdb1 is not a directory. You can find that ls/dev/sdb1 cannot be executed. /dev/sdb1 is something like a pointer, pointing to the raw data blocks of this partition. Before mounting, the system does not know which part of the data in this data block represents files, nor how to operate on them.
    • 10. When inserting a CD, the system actually automatically executes mount /dev/cdrom /media/cdrom. So you can directly manage the contents of the CD in /media/cdrom.
