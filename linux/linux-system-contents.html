Linux System Directory Structure

After logging into the system, type the command in the current command window:

 ls / 

You will see the following as shown in the figure:

Tree directory structure:

The following is an explanation of these directories:

Directory Detailed Description Common Files / Examples
/ Root filesystem, the starting point of all mount points and paths. Contains the system's required subdirectories and entry structure. No specific data files, only subdirectory structure.
/bin Basic commands required for system startup and single-user mode, executable by all users. ls, cp, mv, rm, bash
/sbin System administration and maintenance commands, intended for root. fsck, reboot, shutdown
/usr Main collection of user-level programs and libraries, containing most system software, documentation, and tools. /usr/bin, /usr/lib, /usr/share
/usr/bin Main directory for placing regular user programs. python3, vim, git
/usr/sbin Extended collection of management tools. useradd, apache2ctl
/usr/lib /usrDynamic libraries and modules that the internal programs depend on. Various types of.sodynamic libraries
/usr/local Independent area for locally installed or compiled software. /usr/local/bin, /usr/local/lib
/lib 或 /lib64 Location of the system boot core libraries and the dynamic linker. libc.so.6, ld-linux.so
/etc System-level configuration center, centrally storing all service and system configurations. passwd, group, fstab, ssh/sshd_config
/home Collection of personal home directories for ordinary users. /home/user/.bashrc, /home/user/Documents
/root Home directory of the root user. /root/.ssh/
/var Frequently changing data: logs, caches, database runtime files, etc. /var/log, /var/lib, /var/cache
/var/log Centralized location for all system and service logs. syslog, auth.log, kern.log
/var/cache Application and package manager caches. /var/cache/apt/
/var/lib Persistent state data for services. mysql/, docker/
/tmp Temporary file area for running programs, can be cleared at any time. Temporary files, socket paths
/boot Files required for booting: kernel, initramfs, boot configuration. vmlinuz-*, initrd.img, grub/grub.cfg
/dev Collection of device nodes; files are devices. /dev/sda, /dev/null, /dev/tty0
/proc Virtual filesystem provided by the kernel, displaying real-time information about the system and processes. /proc/cpuinfo, /proc/<pid>/
/sys Status interface for devices, drivers, and kernel subsystems. /sys/class/net/, /sys/block/
/mnt Temporary mount point for manual mounting. /mnt/usb
/media Default location for auto-mounting external devices. /media/user/USB_DRIVE
/run Runtime data storage location, cleared after reboot. *.pid, runtime status socket files

In Linux, the following directories are critical system areas. Accidentally deleting or arbitrarily modifying them will directly damage system operation:

/etc — System Configuration Core

All critical configurations are centralized here. Any incorrect modification may cause services to crash or even prevent the system from booting.

/bin, /sbin, /usr/bin, /usr/sbin — System Command Area

Location of the system's preinstalled commands.

  • /bin、/usr/bin: Basic commands for ordinary users (such aslslocated in/bin/ls）。
  • /sbin、/usr/sbin: System administration commands, mainly used by root.

/var — Dynamic Data Area

Data continuously written during system operation all lands here.
The key point is/var/log, all service logs are stored here; emails, caches, queues, and other contents are also maintained under this directory.

    In Linux or Unix operating systems, all files and directories are organized into an inverted tree structure starting from a root node.

    The topmost layer of the filesystem starts from the root directory, and the system uses/to represent the root directory. Below the root directory, there can be either directories or files, and each directory can contain subdirectory files. Repeating this process can form a huge filesystem.

    There are two special directories in the Linux filesystem. One is the working directory where the user is located, also called the current directory, which can be represented by a single dot.to represent it; the other is the parent directory of the current directory, also called the parent directory, which can be represented by two dots..to represent it.

    • . : Represents the current directory; it can also be represented with ./
    • .. : Represents the parent directory; it can also be represented by ../.

    If a directory or file name starts with a dot ., it means the directory or file is a hidden directory or file (e.g., .bashrc). That is, when searching in the default way, this directory or file is not displayed.

    Required for system boot:

    • /boot：Stores the kernel files used when booting Linux, including link files and image files.
    • /etc：Storesallsystem-requiredconfiguration files和subdirectory list,Changing files in this directory may cause the system to be unable to boot.
    • /lib: Stores basic code libraries (such as C++ libraries), which function similarly to DLL files in Windows. Almost all applications need to use these shared libraries.
    • /sys: This is a major change in the Linux 2.6 kernel. A new filesystem, sysfs, that appeared in the 2.6 kernel is mounted under this directory. The sysfs filesystem integrates information from the following three filesystems: the proc filesystem for process information, the devfs filesystem for devices, and the devpts filesystem for pseudo-terminals. This filesystem is an intuitive reflection of the kernel device tree. When a kernel object is created, the corresponding files and directories are also in the kernel object subsystem

    Command collection:

    • /bin：Stores the most commonly used programs and commands
    • /sbin：Programs and commands that only the system administrator can use.

    External file management:

    • /dev ：Abbreviation of Device, stores Linux external devices.Note:In Linux, accessing devices and accessing files are done in the same way.
    • /media: Windows-likeother devices,For example, USB drives, optical drives, etc. After recognition, Linux will place the devices in this directory.
    • /mnt: Temporarily mount other filesystems. We can mount an optical drive on /mnt/, then enter that directory to view the contents of the optical drive.

    Temporary files:

    • /run: Is a temporary filesystem that stores information since system startup. When the system reboots, the files in this directory should be deleted or cleared. If your system has a /var/run directory, it should point to run.
    • /lost+found: Generally empty; after an abnormal system shutdown, some files are stored here.
    • /tmp: This directory is used to store some temporary files.

    Accounts:

    • /root: Home directory of the system administrator user.
    • /home: The user's home directory, named after the user's account.
    • /usr: Many user applications and files are placed in this directory, similar to the Program Files directory in Windows.
    • /usr/bin：Applications and commands used by system users.
    • /usr/sbin：More advanced management programs and system daemons used by the superuser.
    • /usr/src：Default directory for placing kernel source code.

    Needed during runtime:

    • /var: Stores frequently modified data, such as log files of program running (/var/log directory).
    • /proc: Managememory space!A virtual directory, it is a mapping of system memory. We can directly access this directory to obtain system information. The contents of this directory are not on the hard disk but in memory. We can also directly modify certain files in it to make changes.

    For expansion:

    • /opt: Empty by default; we can install extra software and place it here.
    • /srv: Stores data that needs to be extracted after the service starts(If no server is used, it is empty)
