The Android system was created by Andy Rubin and later acquired by Google; the earliest version was Android 1.1. Now the latest version is Android M, launched at the Google I/O conference on May 28 this year. Interestingly, Android versions are all named after desserts. After reading the above information, we might have this question: With so many system versions, which version should we target for development? This is the Android "fragmentation" problem that every Android developer must face, and this problem is divided into two parts: ① System fragmentation: When developing apps, we may need to ensure compatibility with lower versions, for example, a minimum compatible version of 2.3. Due to the prevalence of custom ROMs, people in China like to make modifications to the stock system, which leads to problems where things work on the stock system but not on custom ROMs, such as camera calls~ ② Screen fragmentation: There are phones with all kinds of screen sizes on the market, 4.3", 4.5", 4.7", 5.0", 5.3"... etc. Besides phones, there are also Android tablets, so during development we may need to handle the issue of screen adaptation. Of course, since we are just learning, we don't need to consider these complex things; we'll delve deeper into them in actual development later!

2. Android System Features and Platform Architecture

System Features:

  • Application framework supportComponent reuse and replacement(If an app follows the framework conventions when released, other apps can also use its modules)
  • DalvikVirtual machine: optimized specifically for mobile devices - Integrated browser: open sourceWebKitEngine
  • SQLiteStructured data storage
  • Optimized graphics libraries, multimedia support, GSM telephony, Bluetooth, etc.
  • Adoptingsoftware stackas the building approach

Platform Architecture Diagram:

Simple Understanding of the Architecture:

  1. Application (Application Layer)The application layer development we usually talk about is carried out at this level, which of course includes a set of built-in system applications, using the Java language
  2. Application Framework (Application Framework Layer)Whether they are system built-in apps or apps we write ourselves, they all need to use this layer. For example, if we want to create a call blacklist or automatically hang up calls, we need to use TelephonyManager. Through this layer, we can easily implement the hang-up operation without worrying about the underlying implementation
  3. Libraries + Android RuntimeAndroid provides us with a set of C/C++ libraries used by different components of the platform, such as the media framework. The Android Runtime is composed of the Android core library set and the Dalvik virtual machine. The Dalvik VM is a virtual machine designed for mobile devices. Its features: it does not require very fast CPU computing speed or a large amount of memory space. Each app runs independently in its own Dalvik VM (each app corresponds to one Dalvik process).   4. Linux KernelThis is where the underlying drivers come in, along with some system services such as security, memory management, and process management
