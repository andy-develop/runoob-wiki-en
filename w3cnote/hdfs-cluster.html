5.0 HDFS Cluster

Category Hadoop Tutorial

The HDFS cluster is built on top of the Hadoop cluster. Since HDFS is the most important daemon of Hadoop, the configuration process of an HDFS cluster is representative of the Hadoop cluster configuration process.

Using Docker can build a cluster environment more conveniently and efficiently.

Configuration on each computer

How Hadoop configures a cluster, and what configurations different computers should have, are questions that arise during learning. This chapter will provide a typical example of configuration, but Hadoop's complex and diverse configuration options go far beyond this.

The NameNode's remote control over DataNodes is implemented through SSH. Therefore, key configuration items should be configured on the NameNode, while non-key node configurations should be configured on each DataNode. In other words, DataNode and NameNode configurations can be different, and configurations among different DataNodes can also differ.

However, for the convenience of setting up the cluster, this chapter will use the same configuration files and synchronize them to all cluster nodes via a Docker image. This is a special note.

Specific steps

The overall approach is as follows: first, we use an image containing Hadoop and configure it so that all nodes in the cluster can share it; then, using it as a prototype, we generate several containers to form a cluster.

Configuration prototype

First, we will use the previously prepared hadoop_proto image to start a container:

docker run -d --name=hadoop_temp --privileged hadoop_proto /usr/sbin/init

Enter the Hadoop configuration file directory:

cd $HADOOP_HOME/etc/hadoop

Now let's briefly describe the purpose of the files here:

FilePurpose
workersRecords the hostname or IP address of all DataNodes
core-site.xmlHadoop core configuration
hdfs-site.xmlHDFS configuration items
mapred-site.xmlMapReduce configuration items
yarn-site.xmlYARN configuration items
Note: YARN's role is to provide resource management services for MapReduce, and it is not needed for now.

We now design such a simple cluster:

  • 1 NameNode: nn
  • 2 DataNodes: dn1, dn2

First, edit workers and change the file content to:

dn1
dn2

Then edit core-site.xml and add the following configuration items inside <configuration>:

<!-- 配置 HDFS 主机地址与端口号 -->
<property>
    <name>fs.defaultFS</name>
    <value>hdfs://nn:9000</value>
</property>
<!-- 配置 Hadoop 的临时文件目录 -->
<property>
    <name>hadoop.tmp.dir</name>
    <value>file:///home/hadoop/tmp</value>
</property>

Configure hdfs-site.xml and add the following configuration items inside <configuration>:

<!-- 每个数据块复制 2 份存储 -->
<property>
    <name>dfs.replication</name>
    <value>2</value>
</property>

<!-- 设置储存命名信息的目录 -->
<property>
    <name>dfs.namenode.name.dir</name>
    <value>file:///home/hadoop/hdfs/name</value>
</property>

Finally, SSH needs to be configured:

ssh-keygen -t rsa -P "" -f ~/.ssh/id_rsa
ssh-copy-id -i ~/.ssh/id_rsa hadoop@localhost

At this point, the cluster prototype is fully configured. You can exit the container and commit the container to a new image cluster_proto:

docker stop hadoop_temp
docker commit hadoop_temp cluster_proto

If necessary, you can delete the temporary image hadoop_temp here.

Deploy the cluster

Next, deploy the cluster.

First, create a dedicated network hnet for the Hadoop cluster:

docker network create --subnet=172.20.0.0/16 hnet

Next, create the cluster containers:

docker run -d --name=nn --hostname=nn --network=hnet --ip=172.20.1.0 --add-host=dn1:172.20.1.1 --add-host=dn2:172.20.1.2 --privileged cluster_proto /usr/sbin/init
docker run -d --name=dn1 --hostname=dn1 --network=hnet --ip=172.20.1.1 --add-host=nn:172.20.1.0 --add-host=dn2:172.20.1.2 --privileged cluster_proto /usr/sbin/init
docker run -d --name=dn2 --hostname=dn2 --network=hnet --ip=172.20.1.2 --add-host=nn:172.20.1.0 --add-host=dn1:172.20.1.1 --privileged cluster_proto /usr/sbin/init

Enter the NameNode:

docker exec -it nn su hadoop

Format HDFS:

hdfs namenode -format

If there are no errors, the next step is to start HDFS:

start-dfs.sh

After a successful startup, the jps command should show the existence of NameNode and SecondaryNameNode. The NameNode does not have a DataNode process, because this process runs on dn1 and dn2.

At this point, you can check the operation of HDFS using the method described in the previous chapter about pseudo-distributed mode. The way to use HDFS is also the same (the NameNode represents the entire cluster).
