Category Programming Techniques

My name is Andrey Karpov. I have studied hundreds of errors caused by "copy-paste". It is safe to say that programmers often make mistakes in the last block of a large section of code. No programming book seems to have discussed this phenomenon, so I decided to write about it myself. I call it the "last line effect".

The Last Line Effect

When programming, programmers often need to write a series of similar structures. Typing line by line is boring and inefficient. That's why they use the "copy-paste" technique: a piece of code is copied and pasted several times, then modified. Everyone knows the downside of this: it's easy to forget to modify something after pasting, eventually breeding bugs. Unfortunately, there is often no better way.

So what pattern did I discover? I found that errors often occur in the last pasted block of code.

Here is a brief example:

inline Vector3int32& operator+=(const Vector3int32& other) {
  x += other.x;
  y += other.y;
  z += other.y;
  return *this;
}

Note this line: "z += other.y;". The programmer forgot to replace 'y' with 'z'.

You might think this is a hypothetical example, but it actually comes from a real application. Next, I will convince you that this is a common high-frequency error. Programmers often make this mistake at the end of a series of similar operations.

I've heard that rock climbers often fall in the last few dozen meters. It's not because they are tired, but precisely because they are overexcited about the upcoming end; they imagine the joy of success, become careless, and finally slip. I guess programmers are the same.

Now, let's look at a set of data.

After studying the database, I isolated 84 code fragments generated by the copy-paste technique. In 41 of them, the error occurred in some middle pasted block. For example:

strncmp(argv[argidx], "CAT=", 4) &&
strncmp(argv[argidx], "DECOY=", 6) &&
strncmp(argv[argidx], "THREADS=", 6) &&
strncmp(argv[argidx], "MINPROB=", 8)) {

The length of the string "THREADS=" is 8 characters, not 6.

In the other 43 code fragments, the error occurred in the last pasted block.

Of course, 43 is not much larger than 41. But note that a program may have many similar code blocks, so errors could occur in the first, second, fifth, or even tenth block. Therefore, in the other blocks we have a relatively uniform distribution, while the last block shows a peak.

On average, the total number of similar code blocks is 5.

Thus, 41 errors are uniformly distributed among the first 4 code blocks, with an average of 10 errors per block.

However, the last block contains 43 errors!

The distribution diagram below highlights this phenomenon:

Overview diagram of error distribution in five similar code segments

Therefore, we can summarize a rule:

The probability of making an error in the last pasted code block is 4 times that of other code blocks.

This rule may not be universal. It is just an interesting finding, and its practical value is to remind you to stay vigilant when writing the last block.

Conclusion

This article tells you that the copy-paste technique is likely to have a 4 times higher probability of error in the last pasted code block than in other blocks.

This is related to human psychology, not technical skill. The article shows that even experienced programmers in projects like Clang or Qt make this kind of mistake.

I hope this discovery of the phenomenon is helpful to programmers, and perhaps it will encourage them to study our bug database. I believe this will help find new patterns in these errors and summarize new programming recommendations.
