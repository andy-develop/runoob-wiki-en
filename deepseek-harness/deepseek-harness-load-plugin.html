DeepSeek Harness loads local plugins

上一篇DeepSeek Harness 第一个插件We've written the source code for hello-plugin; next, we'll load it into the Web UI.

Here we'll use two things: the patch overlay cordis.yml and the --patch startup parameter.

scratch-plugin directory structure

Previously we created scratch-plugin/src, now add a cordis.yml.

The structure of the entire temporary project is as follows:

scratch-plugin/
├── src/
│   └── my-plugin.ts    # 插件源码（上一篇写的 hello-plugin）
└── cordis.yml          # patch 覆盖层：告诉框架插入哪个插件

cordis.yml 的 insert

Run `pwd` at the repository root to get the absolute path.

Then create scratch-plugin/cordis.yml with the following content:

实例

# 文件路径：scratch-plugin/cordis.yml
# 这是一个 Web 覆盖层（overlay），只负责插入本地插件
- insert:
    - id: hello
      # name 是插件文件路径，必须是绝对路径！
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'

Replace /absolute/path/to/deepseek-harness with the actual path printed by pwd.

The plugin path must be an absolute path.

Patch files only contribute configuration; they do not change the profile directory used by the loader when resolving module paths.

Start with --patch

Start the Web UI with this overlay:

pnpm dsh web --patch ./scratch-plugin/cordis.yml

During startup, the terminal will print [hello-plugin] plugin loaded!.

打开 http://127.0.0.1:3080，在设置插件列表中搜索 hello，可以看到我们安装的插件。

工作原理

dsh layers multiple configuration sources in order into a single final configuration.

The cordis.yml passed via --patch is an overlay that gets merged into the profile at startup.

概念是什么作用
profileA launchable assembly configurationDetermine which bundles make up the Web UI.
patch overlayAdditional yml overlaid at startupInsert local plugins and override a configuration item
insertSyntax for inserting plugins in a patchLoad plugins by absolute path via `name`.

Tip: --patch is suitable for local development and debugging.

When you need to deliver the plugin to others, use the bundle approach; see Article 21.
