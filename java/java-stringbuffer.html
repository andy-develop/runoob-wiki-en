Java StringBuffer and StringBuilder Classes

When modifying strings, you need to use the StringBuffer and StringBuilder classes.

Unlike the String class, objects of the StringBuffer and StringBuilder classes can be modified multiple times without creating new unused objects.

When using the StringBuffer class, every operation is performed on the StringBuffer object itself rather than generating a new object, so if you need to modify strings, StringBuffer is recommended.

The StringBuilder class was introduced in Java 5. The biggest difference between it and StringBuffer is that StringBuilder's methods are not thread-safe (cannot be accessed synchronously).

Since StringBuilder has a speed advantage over StringBuffer, it is recommended to use the StringBuilder class in most cases.

Example

public class RunoobTest{ public static void main(String[] args){ StringBuilder sb = new StringBuilder(10); sb.append("Runoob.."); System.out.println(sb); sb.append("!"); System.out.println(sb); sb.insert(8, "Java"); System.out.println(sb); sb.delete(5,8); System.out.println(sb); } }

The compilation and execution result of the above example is as follows:

Runoob..!
Runoob..Java!
RunooJava!

However, when the application requires thread safety, the StringBuffer class must be used.

Test.java file code:

public class Test{ public static void main(String[] args){ StringBuffer sBuffer = new StringBuffer("Runoob Tutorial official website:"); sBuffer.append("www"); sBuffer.append(".runoob"); sBuffer.append(".com"); System.out.println(sBuffer); } }

    In Java, there are certain differences between StringBuffer and String. First, String is modified by final, and its length is immutable. Even if you call String's concat method, it still concatenates the strings and re-creates an object, assigning the concatenated String value to the newly created object. However, StringBuffer's length is mutable; calling StringBuffer's append method changes the length of StringBuffer. Moreover, compared with StringBuffer, once String changes in length, it is very memory-consuming.

    What are the applicable scenarios for StringBuilder and StringBuffer in Java?

    The simplest answer is that StringBuffer basically has no applicable scenarios. You should choose to use StringBuilder in all cases, unless you really encounter a scenario that requires thread safety. If you do, please be sure to leave a comment here to notify me.

    Then, one more point: regarding thread safety, even if you really encounter such a scenario, unfortunately, I'm afraid that in 99.99....99% of cases there is still no need to choose StringBuffer, because StringBuffer's thread safety only ensures that the JVM does not throw exceptions and continues to execute smoothly; it does not guarantee correct logic or correct call order. Most of the time, what we need is not just thread safety, but locks.

    Finally, why does StringBuffer exist? If it really has no value, why does the JDK provide this class? The answer is too simple: because there was no StringBuilder in the earliest days. Someone at Sun, for some stupid reason, decided to make StringBuffer thread-safe. Then about 10 years later, people finally realized what a stupid decision it was, and realized how much this stupid decision had contributed to rumors that Java was slow during those 10 years. So in JDK 1.5, they finally decided to provide a non-thread-safe StringBuffer implementation and named it StringBuilder. By the way, it seems that javac started from this version to implicitly rewrite all string operations concatenated with plus signs into StringBuilder. That is to say, starting from JDK 1.5, concatenating strings with plus signs no longer has any performance penalty.

    As many comments have pointed out, what I said above, "concatenating strings with plus signs no longer has any performance penalty," is not rigorous. Strictly speaking, if there is no loop, concatenating strings with plus signs on a single line has no performance penalty; the Java compiler will implicitly replace it with StringBuilder. But in the presence of a loop, the compiler cannot replace it intelligently enough, and there will still be unnecessary performance loss. Therefore, when concatenating strings in a loop, just use StringBuilder honestly.
