Codex Integration with Deepseek

In August 2026, DeepSeek officially announced support for integration with Codex. deepseek-v4-flash was launched first, and deepseek-v4-pro will also support integration later.

Codex is an AI programming assistant launched by OpenAI. It communicates with models through the Responses API, and the DeepSeek API natively supports this protocol format.

All client forms of Codex -- Codex CLI, ChatGPT desktop, and the Codex IDE plugin for VS Code -- share the same local configuration file, so you only need to configure it once to use DeepSeek models across all forms.

Prerequisites

  • Codex CLI or ChatGPT desktop must be installed and launched at least once (so that the ~/.codex directory is created).
  • Go to the DeepSeek Open Platformhttps://platform.deepseek.com/api_keysApply for an API Key (starting with sk-).

Configure DeepSeek as the model provider

DeepSeek officially provides two integration methods. Method 1 is recommended.

Method 1: One-click configuration script (Recommended)

macOS / Linux: run in the terminal:

bash <(curl -fsSL https://cdn.deepseek.com/api-docs/codex-deepseek-setup.sh)

Windows: run in PowerShell:

irm https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.ps1 | iex

After running, follow the menu prompts to select the model to use. The first run will ask for your API Key.

For our first run, select 1 optionModify Codex configuration to use the deepseek-v4-flash model：

Later, if we want to restore the default configuration, we can also run this script and select 3 to restore.

Next, it will prompt for the API key input. If it has already been configured in an environment variable, it will use the API key provided by the environment variable DEEPSEEK_API_KEY and skip the prompt:

After restarting ChatGPT, you can see DeepSeek's models:

This script will automatically complete the following tasks:

  • Back up existing configuration: put~/.codex/config.tomlback up to~/.codex/backup-deepseek/, convenient to restore at any time.

  • Write to the model directory file ~/.codex/models.json: Declares the metadata of the DeepSeek model to Codex (context window length, supported reasoning effort levels, tool calling format, etc.), so that Codex can call DeepSeek just like calling built-in models.

  • Modify ~/.codex/config.toml: Only rewrite the necessary fields (see field descriptions below), and add a new[model_providers.deepseek]configuration section. Existing configurations such as MCP servers and project trust levels will be preserved. If conflicting fields are found, they will be automatically removed and the removal reason will be printed.

  • Syntax validation: Before writing, it will first validate theconfig.toml / models.jsonvalidity. If validation fails, the process aborts and will not damage existing files.

Afterwards, you can run the script again at any time to switch models, or restore to the default configuration before installation (item 3 in the menu).
