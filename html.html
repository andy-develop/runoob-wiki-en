    The difference between htm and html.

    The former is Hypertext Markup

    The latter is Hypertext Markup Language

    It can be said that htm = html

    At the same time, both are extensions for static web page files. The extensions can be swapped with each other without causing errors (this refers to opening; but for a link, if it points to an htm file and that htm file is renamed to html, then the link cannot be found).

    那为什么出现两种文件格式呢？

    htm originates from the old 8.3 file format. The DOS operating system only supports extensions with a length of three characters, so it is htm. But under Windows, there is no difference between HTM and HTML; html is named for the long file name format. So htm exists for compatibility with the past DOS naming format, and there is no difference in effect. Previously, htm and html were used as hypertext files on different servers, but now they are universally interchangeable.

    What is the 8.3 file format? This is a short filename file format on old 16-bit Win95 or Win98 file systems, where the extension is limited to 3 characters and the filename is limited to 8 characters. If you need to interact with a 16-bit system, for example, to pass a path to a 16-bit program, you cannot use long filenames and must convert it. For example, convert "C ： /MyLongestPath/MyLongerPath/MyFilename.txt" to "C ： /Mylong~1/MyLong~2/Myfile~1.txt".

    What is the use of knowing this? Under DOS with the FAT disk format, only the 8.3 file format is supported. If you want to develop applications in this environment, you should pay attention to this file format issue. Under NTFS, this file format is compatible by default, and long filenames are also supported. You can also adjust the registry to disable support for the 8.3 file format.

    后缀名选择：用 htm 还是用 html ?

    Long file extensions are recommendedhtml 。

    Naming should follow the principles of clear meaning, conciseness, and consistency. Clear meaning means you know the meaning at the sight of the name. For example, htm (hypertext markup) and html (hypertext markup language) here both use the acronyms of English words, so their meanings are clear. Conciseness requires variable names to be as short as possible; for example, the extension here uses acronyms rather than full words. The consistency principle requires that a large number of variable names in the same environment follow the same rules. For example, some friends, after becoming accustomed to Linux folder naming rules, still refuse to use spaces when naming new folders on Windows, causing the new folder names to be inconsistent with the old folder naming rules.

    The consistency principle is often more important. For example, in collaborative development, we cannot each stick to our own ways, artificially increasing development difficulty.

    From Yilu Fengchen's notes, we learned that htm is a legacy naming method from the 8.3 character limit, and now we do not follow the 8.3 rule when naming. Therefore, when choosing between htm and html, we should also choose html, which uses unlimited-length naming.

Mainstream browsers supporting the HTML5 standard all recognize this declaration.
