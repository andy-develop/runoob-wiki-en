C# 数据类型

In C#, variables can be divided into the following types:

  • 值类型（Value types）
  • 引用类型（Reference types）
  • Pointer types

引用类型（Reference types）

Reference types do not contain the actual data stored in the variable, but they contain references to the variable.

In other words, they refer to a memory location. When multiple variables are used, reference types can point to a memory location. If the data at the memory location is changed by one variable, other variables will automatically reflect this change in value.内置的Reference types include:object、dynamic 和 string。

Object type

对象（Object）类型is the ultimate base class of all data types in the C# Common Type System (CTS). Object is an alias for the System.Object class. Therefore, the object (Object) type can be assigned values of any other type (value types, reference types, predefined types, or user-defined types). However, before assigning a value, type conversion is required.

When a value type is converted to an object type, it is called装箱; on the other hand, when an object type is converted to a value type, it is called拆箱。

object obj;
obj = 100; // 这是装箱

Dynamic type

You can store any type of value in a dynamic data type variable. Type checking for these variables occurs at runtime.

Syntax for declaring a dynamic type:

dynamic <variable_name> = value;

例如：

dynamic d = 20;

Dynamic types are similar to object types, but type checking for object type variables occurs at compile time, while type checking for dynamic type variables occurs at runtime.

String type

字符串（String）类型allows you to assign any string value to a variable. The string (String) type is an alias for the System.String class. It is derived from the object (Object) type. Values of the string (String) type can be assigned in two forms: quotation marks and @ quotation marks.

例如：

String str = "runoob.com";

A @-quoted string:

@"runoob.com";

In C#, a string can be prefixed with @ (called a "verbatim string") to treat escape characters (\) as ordinary characters, for example:

string str = @"C:\Windows";

等价于：

string str = "C:\\Windows";

In an @ string, you can break lines arbitrarily; line breaks and indentation spaces are all counted within the string length.

string str = @"<script type=""text/javascript"">
    <!--
    -->
</script>";

User-defined reference types include: class, interface, or delegate. We will discuss these types in later chapters.

Pointer types

Pointer type variables store the memory address of another type. Pointers in C# have the same functionality as pointers in C or C++.

Syntax for declaring a pointer type:

type* identifier;

例如：

char* cptr;
int* iptr;

We will discuss pointer types in the chapter "Unsafe Code."

    About boxing and unboxing

    Boxing: converting a value type to an object type, example:

    int val = 8;
object obj = val;//整型数据转换为了对象类型（装箱）

    Unboxing: converting an object type that was previously converted from a value type back to a value type, example:

    int val = 8;
object obj = val;//先装箱
int nval = （int）obj;//再拆箱

    Only data that has been boxed can be unboxed.

    The difference between String and string in C#

    string is a class in C#, String is a class in .NET Framework (it will not display blue in the C# IDE). C# string maps to .NET Framework's String. If you use string, the compiler will compile it into String, so if you directly use String, you can let the compiler do a little less work.

    If using C#, it is recommended to use string, which is more in line with the specification. string always represents System.String (1.x) or ::System.String (2.0). String only represents System.String when there is "using System;" in front and there is no type named String (class, struct, delegate, enum) in the current namespace. string is a keyword, String is not. That is to say, string cannot be used as the name of a class, struct, enum, field, variable, method, or property, while String can.

    String is the CLR type name (also considered a keyword), while string is a keyword in C#. During compilation, the C# compiler converts string to String by default, adding a few extra lines of conversion code. In many cases, it is recommended to use CLR types rather than C# types (this is the experts' advice). For example, when using int, it is better to use Int32, and so on. Many times it is a matter of habit and convention. Another difference is that they appear in different colors in VS: String is green, while string is blue.

    Each value type has an independent memory area that stores its own value; when it is called, what is called is its value, while reference types call the address in memory. For example, define a reference type a1=10; at this time, 10 is stored in memory. When a1 is assigned to a2, both of them reference the same memory space, and a2's value will be stored as a1's value. When a2 is changed to 20, since a1 and a2 reference the same [memory], a1 also becomes 20. This is the reference type. For value types, when a1 is assigned to a2, a new space is opened for a2 to store a1's value. When a2 is changed to 20, 20 is stored in a2's space, which has no relation to a1.

    On the relationship among value types, reference types, and the "stack" and "heap"

    Value types: when a value type is declared, a memory space is opened in the "stack" to store the corresponding value. When the value of the value type changes, the value stored in that memory space is directly modified. Example:

    int n1 = 5;
int n2 = n1;
Console.WriteLine(n1 + "  "+ n2);    // 5  5
n2 = 7;
Console.WriteLine(n1 + "  " + n2)    // 5  7

    Here, first a memory space is allocated in the "stack" to store the value 5 of n1, then a new memory space is allocated in the "stack" to store the value 5 of n2, so the displayed result is 5 5. Then the value stored in the memory space corresponding to n2 in the "stack" is changed to 7, so the displayed result is 5 7.

    Reference types: when a reference type is declared, first a memory space is opened in the "heap" to store the corresponding value, and then a memory space is opened in the "stack" to store the address of the memory space opened in the "heap". When the system calls a reference type, it first obtains the address from the "stack", and then, based on the address, finds the corresponding memory space in the "heap" to obtain the corresponding value.     But string is a special reference type. First, look at the following code:

    string a = "123";
string b = a; 
Console.WriteLine(a+" "+b);  //123 123
string b = "456";
Console.WriteLine(a+" "+b);  //123 456

    Unlike arrays, when a is assigned to b, first a new memory space is allocated in the "heap" (assume: 0X101) to store the value 123, then a memory space (b) is allocated in the "stack" to store the address 0X101, so the output result is 123 123.

    When modifying the value of b, it does not modify the value in the memory space 0X101 in the "heap". Instead, it allocates a new memory space in the "heap" (assume: 0X210) to store the modified value of b, and then changes the address stored in the memory space corresponding to b in the "stack" to 0X210, so the output result is 123 456. The memory space 0X101 in the "heap" will be reclaimed in the next garbage collection.

    Differences between value types and reference types:

    From a memory perspective, value types are operations on the stack, while reference types are operations on the heap.

    (This results in => value types have fast access speed, while reference types have slow access speed.)

    In essence, value types represent actual data, while reference types represent pointers or references to data stored in the memory heap.

    (Value types are the size of the space occupied by the specific numeric value, while reference types are the space address that stores that numeric value.)

    In terms of origin, value types inherit from System.ValueType, and reference types inherit from System.Object.

    In particular: structs are value types, while classes and string are reference types.

    When a value type is converted to an object type, it is called装箱; on the other hand, when an object type is converted to a value type, it is called拆箱。

    Dynamic types are similar to object types, but type checking for object type variables occurs at compile time, while type checking for dynamic type variables occurs at runtime.
