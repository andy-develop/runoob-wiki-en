C# 类型转换

In C#, type conversion is the process of converting a value of one data type to another data type.

Type conversion in C# can be divided into two types:Implicit type conversion和Explicit type conversion(also known as forced type conversion).

Implicit type conversion

Implicit conversion is a conversion that does not require writing code to specify it; the compiler performs it automatically.

Implicit conversion refers to the fact that when converting a data type with a smaller range to a data type with a larger range, the compiler automatically completes the type conversion. These conversions are C# default conversions performed in a safe manner and do not cause data loss.

For example, from int to long, from float to double, etc.

Converting from a small integer type to a large integer type, or from a derived class to a base class. When assigning a variable of byte type to a variable of int type, the compiler will automatically convert the byte type to int type without requiring explicit conversion.

实例

byte b = 10;
int i = b; // 隐式转换，不需要显式转换

Assigning an integer to a long integer, or assigning a floating-point number to a double-precision floating-point number, this kind of conversion does not cause data loss:

实例

int intValue = 42;
long longValue = intValue; // 隐式转换，从 int 到 long

显式转换

Explicit type conversion, also known as forced type conversion, requires the programmer to explicitly specify it in the code.

Explicit conversion refers to the fact that when converting a data type with a larger range to a data type with a smaller range, or converting one object type to another object type, a cast operator is required for explicit conversion. Forced conversion can cause data loss.

For example, assigning an int type variable to a byte type variable requires explicit conversion.

实例

int i = 10;
byte b = (byte)i; // 显式转换，需要使用强制类型转换符号

Cast to an integer type:

实例

double doubleValue = 3.14;
int intValue = (int)doubleValue; // 强制从 double 到 int，数据可能损失小数部分

Cast to a floating-point type:

实例

int intValue = 42;
float floatValue = (float)intValue; // 强制从 int 到 float，数据可能损失精度

Cast to a string type:

实例

int intValue = 123;
string stringValue = intValue.ToString(); // 将 int 转换为字符串

The following example demonstrates an explicit type conversion:

实例

using System;

namespace TypeConversionApplication
{
    class ExplicitConversion
    {
        static void Main(string[] args)
        {
            double d = 5673.74;
            int i;

            // 强制转换 double 为 int
            i = (int)d;
            Console.WriteLine(i);
            Console.ReadKey();
           
        }
    }
}

When the above code is compiled and executed, it produces the following results:

5673

When performing type conversion, the following points need to be noted:

  • Implicit conversion can only convert a data type with a smaller range to a data type with a larger range, and cannot convert a data type with a larger range to a data type with a smaller range;
  • Explicit conversion may cause data loss or reduced precision, so compatibility checks of data types are required;
  • For object type conversion, compatibility checks for type conversion and safety checks for type conversion are required.

Type conversion methods

C# provides various type conversion methods, such as the Convert class, Parse method, and TryParse method, which can help handle conversions between different data types.

Using the Convert class

The Convert class provides a set of static methods that can convert between various basic data types.

实例

string str = "123";
int num = Convert.ToInt32(str);

Using the Parse method

The Parse method is used to convert a string to the corresponding numeric type, and it throws an exception if the conversion fails.

实例

string str = "123.45";
double d = double.Parse(str);

Using the TryParse method

The TryParse method is similar to Parse, but it does not throw an exception; instead, it returns a Boolean value indicating whether the conversion succeeded.

实例

string str = "123.45";
double d;
bool success = double.TryParse(str, out d);

if (success) {
    Console.WriteLine("转换成功: " + d);
} else {
    Console.WriteLine("转换失败");
}

Custom type conversion

C# also allows you to define custom type conversion operations by defining the implicit or explicit keyword in a type.

实例

using System;

public class Fahrenheit
{
    public double Degrees { get; set; }

    public Fahrenheit(double degrees)
    {
        Degrees = degrees;
    }

    // 隐式转换从Fahrenheit到double
    public static implicit operator double(Fahrenheit f)
    {
        return f.Degrees;
    }

    // 显式转换从double到Fahrenheit
    public static explicit operator Fahrenheit(double d)
    {
        return new Fahrenheit(d);
    }
}

public class Program
{
    public static void Main()
    {
        Fahrenheit f = new Fahrenheit(98.6);
        Console.WriteLine("Fahrenheit object: " + f.Degrees + " degrees");

        double temp = f; // 隐式转换
        Console.WriteLine("After implicit conversion to double: " + temp + " degrees");

        Fahrenheit newF = (Fahrenheit)temp; // 显式转换
        Console.WriteLine("After explicit conversion back to Fahrenheit: " + newF.Degrees + " degrees");
    }
}

In the above example, we defined a Fahrenheit class and implemented an implicit conversion from Fahrenheit to double and an explicit conversion from double to Fahrenheit.

The output result will be displayed as follows:

Fahrenheit object: 98.6 degrees
After implicit conversion to double: 98.6 degrees
After explicit conversion back to Fahrenheit: 98.6 degrees

    Convert.ToInt32() 与 int.Parse() 的区别

    没搞清楚Convert.ToInt32 和 int.Parse()When it comes to the subtle differences, never use them carelessly; otherwise, it may produce unpredictable results. For example, if we take the value of a parameter page from a URL, we know this value is an int, so we can useConvert.ToInt32(Request.QueryString["page"])，也可以用int.Parse(Request.QueryString["page"])However, if the page parameter does not exist in the URL, the former will return 0, and 0 may be a valid value, so you do not know that the parameter did not exist in the URL in the first place and continue processing the next step, which may produce unexpected results. With the latter approach, if the page parameter is missing, an exception will be thrown. We can catch the exception and then handle it accordingly, such as prompting the user that the parameter is missing, rather than treating the parameter value as 0.

    (1) The biggest difference between these two methods is how they handle null values:Convert.ToInt32(null)will return 0 without producing any exception, butint.Parse(null)An exception will be generated.

    (2) The difference when rounding data

    • a.Convert.ToInt32(double value): if value is a number exactly between two integers, it returns the even one of the two; that is, 3.5 converts to 4, 4.5 converts to 4, and 5.5 converts to 6. However, 4.6 can convert to 5, and 4.4 converts to 4.
    • b.int.Parse("4.5") 直接报错:"The input string is not in the correct format."。
    • c.int(4.6) = 4. When Int converts other numeric types to Int, there is no rounding; it is a forced conversion.

    (3) Differences in the type being convertedint.Parseis to convert String to int,Convert.ToInt32It converts an object inherited from Object to int (there can be many other types of data). You get an object, and you want to convert it to int; useint.Parseit is not acceptable; you need to useConvert.ToInt32。

    1）For converting objects, Convert.ToInt32() can handle multiple types (for example, bool, DateTime, etc. in addition to numeric types). int.TryParse() and int.Parse() can only handle integer string types (that is, the form after various integer types call ToString(); floating-point types are not allowed; otherwise, int.Parse() will show an error that the input string format is incorrect, and int.TryParse() will also return false with the output parameter being 0). (int) can only be used with numeric types (for example, float, int, uint, etc.).

    2）For a NULL value, from the perspective of runtime errors, (int) forced conversion and int.Parse() cannot accept NULL; Convert.ToInt32() actually makes a judgment before conversion. If the parameter is NULL, it directly returns 0; otherwise, it calls int.Parse() for conversion. int.TryParse() actually performs exception handling on int.Parse(). If an exception occurs, it returns false and sets the output parameter to 0.

    3）Regarding the rounding of floating-point types, only Convert.ToInt32() and (int) can perform the conversion, but they also round the value. Convert.ToInt32() uses rounding (round half up), while (int) truncates the integer part of the floating-point number and ignores the fractional part. For example, Convert.ToInt32(1.499d) and (int)1.499d both return 1, Convert.ToInt32(1.5d) returns 2, while (int)1.5d still returns 1.

    4）Regarding overflow, when converting a larger data type to a smaller one, both Convert.ToInt32() and int.Parse() will throw an overflow error, stating that the value is too large or too small for Int32, while (int) does not throw an error but returns -1.

    Thus, we should be cautious when choosing a conversion method before performing data conversion. If it is a numeric type, consider using an (int) cast directly. If it is an integer string type, consider using int.Parse() for conversion. If it is neither of these two types, then consider using Convert.ToInt32() for conversion.
