Hermes Agent CLI 命令行

CLI (Command Line Interface) is the most native way to interact with Hermes Agent, and also the most feature-complete entry point.

This chapter systematically introduces the three operation modes of CLI, session management, slash commands, TUI interface, shortcut operations, and scripting usage techniques.

Three Running Modes

Hermes CLI provides three operation modes, from simple Q&A to interactive sessions to pure keyboard operation, covering different usage scenarios.

Mode 1: Interactive session (hermes chat)

This is the most commonly used mode—launching a continuous multi-turn conversation session.

Start an interactive session (using the default Profile):

hermes chat

After starting, you enter the conversation interface, the prompt changes to, and after typing a message, press Enter to send; Agent begins to reply:

Once in an interactive session, you can send multiple messages continuously, and Agent will remember the previous conversation context.

This is the most natural way to use it in daily development—just like chatting with a colleague on Slack.

Mode 2: One-time query (-q / --query)

No need to enter an interactive session; pass in a question directly and get a reply, suitable for scripting and quick queries.

实例

# 一次性查询：发送问题，获得回复后退出
hermes chat -q "用 Python 写一个快速排序函数"

# 结合 Profile 使用
coder chat -q "审查 src/main.py 的代码风格"

# 在 Shell 脚本中使用
hermes chat -q "将以下日志中的错误行提取出来" < error.log

-qKey features of the modes:

  • Non-interactive; Agent exits immediately after completing the reply.
  • Returns a standard exit code, allowing scripts to determine success or failure.
  • Supports pipes and redirection

Mode 3: TUI terminal interface (hermes --tui)

TUI (Terminal User Interface) provides a full-screen terminal interface with pure keyboard operation.

实例

# 启动 TUI 模式
hermes --tui

# TUI 模式下：
# 上下箭头：浏览对话历史
# Ctrl+N：新建会话
# Ctrl+S：切换侧边栏（文件、工具历史等）
# Ctrl+C：中断 Agent 当前操作
# / 开头：输入斜杠命令

Unique advantages of TUI mode:

  • The sidebar can simultaneously display conversation, file changes, and tool call history.
  • Pure keyboard operation, no mouse required
  • Suitable for long-duration deep work scenarios

Comparison of Three Modes

模式命令交互方式适合场景
交互式会话hermes chatMulti-turn dialogue, input a message then wait for replyDaily development, complex tasks
一次性查询hermes chat -q "..."Single query, exits after replyScripting, quick queries
TUIhermes --tuiFull-screen keyboard operation, multi-panelDeep work, file-operation intensive

会话管理

A session is the basic unit of conversation in the CLI. Each session has its own independent context, token count, and session ID.

Continue and Resume Sessions

实例

# 继续最近一次会话（中断后恢复）
hermes --continue
hermes chat --continue

# 按会话标题恢复（前提是已用 /title 命名过）
hermes -c "重构认证模块"

# 按会话 ID 精确恢复
hermes -r 20260305_091234_abc12345

When resuming a session, Agent retains the full conversation context, including previous tool call records and LLM reasoning history.

开启新会话

实例

# 在交互式会话中使用斜杠命令
/new

# 或
/reset

# 效果相同：结束当前会话，开启新会话，
# Agent 会重新加载系统提示词和持久记忆

New sessions do not retain previous conversation context, but persistent memory (MEMORY.md and USER.md) remains visible.

Session Title Management

Hermes automatically generates a session title after the first round of conversation; you can also manually name it:

实例

# 在会话中设置标题（用于后续按标题恢复）
/title 数据库迁移方案讨论

# 查看当前会话信息（ID、标题、Token 用量等）
/status

上下文压缩

When the conversation history becomes too long and approaches the context window limit, you can manually trigger compression:

实例

# 手动压缩对话上下文
/compress

# 压缩后，旧内容被摘要化以释放空间，
# 新消息可以继续发送。
# 压缩后的会话创建自动世系（Auto-Lineage）：
# "数据库迁移" → "数据库迁移 #2"

Automatic compression is triggered by Hermes when the context approaches the limit. /compress simply allows you to trigger it manually in advance. Both have the same effect.

Common Slash Commands

In interactive session and TUI mode, with/Input starting with / is recognized as a slash command.

The following are the most commonly used CLI commands, grouped by function.

会话控制

命令功能
/new 或 /reset开启新会话
/title <名称>Set the current session title
/statusShows session ID, title, and token usage.
/usageShows token consumption details for the current session.
/compressManually compress conversation context
/resume [标题]Restore a previously named session

任务控制

命令功能
/stopInterrupts the task Agent is currently executing.
/retryMakes Agent regenerate the previous reply.
/undoUndoes the previous round of conversation (removes the last Q&A pair).
/background <任务>Run Tasks Asynchronously in Background Sessions

/undo is a conversation-level undo—it removes the last Q&A round from the session history, returning Agent's context to the state before the previous reply. This is different from /retry (which keeps the original Q&A and asks Agent to re-answer).

多行输入

When you need to send messages containing line breaks (such as code blocks):

实例

# 方法一：使用 \n 表示换行
hermes chat -q "审查以下代码：\n\ndef hello():\n    print('world')"

# 方法二：使用 Heredoc（Shell 语法）
hermes chat -q "$(cat << 'EOF'
请分析这个错误堆栈：

Traceback (most recent call last):
  File "app.py", line 42, in <module>
    main()
  File "app.py", line 38, in main
    result = process(data)
TypeError: 'NoneType' object is not iterable

请给出修复方案。
EOF
)"

Pipes and Redirection

-qThe mode natively supports standard Unix pipes:

实例

# 将文件内容作为上下文发送给 Agent
cat error.log | hermes chat -q "分析这些错误日志，找出根本原因"

# 将 Agent 的回复保存到文件
hermes chat -q "生成项目的 README.md" > README.md

# 在管道中使用 Agent 作为过滤器
cat data.csv | hermes chat -q "提取所有邮箱地址，每行一个" > emails.txt

Combined with Profile command aliases

Each Profile automatically generates dedicated command aliases, no need to-p标志：

实例

# 直接使用 Profile 别名，简洁自然
coder chat -q "重构这个函数"
researcher chat -q "搜索最新的 Transformer 论文"
admin gateway status

# 等价于
hermes -p coder chat -q "重构这个函数"
hermes -p researcher chat -q "搜索最新的 Transformer 论文"
hermes -p admin gateway status

Approvals and Security Controls

审批模式

When executing dangerous commands in the CLI, Hermes displays an approval prompt:

Agent 请求执行: rm -rf /tmp/build/*
原因: 清理构建缓存
[approve/deny]: _

You can decide in real time within the session to approve or reject.

The approval mode is configured in config.yaml:

实例

# 文件路径：~/.hermes/config.yaml
approvals:
  mode: manual        # manual（默认，每个危险命令需审批）
                      # smart（智能判断，风险低的自动批准）
                      # off（关闭审批，不推荐）
  timeout: 60         # 等待审批的秒数，超时自动拒绝

YOLO 模式

When you are sure what Agent is about to do is safe (such as operations in a project you are familiar with), you can temporarily skip approval:

实例

# 第一次输入 /yolo：开启 YOLO 模式
# 当前会话中所有命令自动审批
/yolo

# Agent 开始执行操作，不再弹出审批提示...

# 再次输入 /yolo：关闭 YOLO 模式，恢复审批
/yolo

YOLO mode only takes effect in the current session; new sessions automatically restore the approval mode configured in config.yaml. This ensures that temporary relaxation does not become a permanent vulnerability.

脚本化使用

Using Hermes in shell scripts

-qThe mode's exit codes and standard output allow Hermes to integrate seamlessly into shell scripts:

实例

#!/bin/bash
# 文件路径：scripts/auto-review.sh
# 自动代码审查脚本——对 Git 变更的文件逐一审查

# 获取所有变更的 Python 文件
changed_files=$(git diff --name-only HEAD~1 | grep '\.py$')

for file in $changed_files; do
    echo "=== 审查:$file ==="

    # 使用 Hermes 审查代码，结果直接输出到终端
    hermes chat -q "审查以下 Python 文件的代码风格和潜在问题：
$(cat "$file")

请以列表形式给出发现的问题和建议。" 2>/dev/null

    # 检查退出码
    if [ $? -ne 0 ]; then
        echo "[警告]$file审查过程中出现错误"
    fi

    echo ""
done

结合 Git Hooks

The following is a Git pre-commit hook example—letting Agent check the code before committing.

实例

#!/bin/bash
# 文件路径：.git/hooks/pre-commit
# Git pre-commit hook：提交前由 Agent 检查代码

# 获取暂存区中变更的文件列表
staged_files=$(git diff --cached --name-only)

if [ -z "$staged_files" ]; then
    exit 0
fi

echo "Hermes Agent 正在检查代码变更..."

# 让 Agent 审查暂存的变更
result=$(hermes chat -q "审查以下 Git 暂存区的代码变更，\
只报告严重问题（安全漏洞、逻辑错误、破坏性变更）。\
如果没有严重问题，回复 PASS。\
\
变更文件：\n$staged_files\n\
详细 diff：\n$(git diff --cached)" 2>/dev/null)

echo "$result"

# 如果 Agent 发现了严重问题，阻止提交
if echo "$result" | grep -q "PASS"; then
    echo "审查通过"
    exit 0
else
    echo ""
    echo "Agent 发现了需要关注的问题。"
    echo "如果确认无误，使用 git commit --no-verify 跳过此检查。"
    exit 1
fi

定时执行

Combined with the system's cron or Hermes' built-in Cron system, CLI tasks can be executed periodically—but it is recommended to use Hermes' built-in Cron (viahermes cron create), because it can directly deliver results to the message platform.
