Hermes Agent Skills

If the memory system allows Hermes to rememberwho are you, then the Skills system allows Hermes to rememberHow to Do Things。

Skills are Hermes Agent's procedural memory.

Skills allow the agent to create reusable workflows from experience and reuse them in future sessions.

The Skills system is Hermes Agent's core differentiating feature—it is the only agent with a built-in learning loop, capable of creating skills, improving skills through use, and maintaining knowledge across sessions.

What is a skill?

Skills are a set of instructions and tools that define agent behavior. They can:

  • Automated workflow— Encapsulating common task patterns
  • Cross-session learning— Saving and reusing successful solutions
  • Share with the community— Publishing and installing skills created by others
  • Self-Improvement— Continuously improving through use

For more information, refer to the Skills tutorial:https://www.example.com/ai-agent/skills-agent.html。

Rule of thumb: if you would write it into a reference document, it's a skill; if you would put it on a sticky note, it's a memory.

Progressive disclosure: a token-efficient loading mechanism

One of the smartest designs in the skill system isProgressive disclosure—The agent does not stuff all skill content into context at once, but loads it in three layers on demand.

Level 0: skills_list()              → [{name, description, category}, ...]
                                       会话启动时加载，约 3,000 tokens
                                       ↓ 只有需要用某个技能时，才继续
Level 1: skill_view(name)           → 完整 SKILL.md 内容 + 元数据
                                       ↓ 只有需要参考文档时，才继续
Level 2: skill_view(name, path)     → 技能内的特定 references/ 文件

The practical significance of this design is very direct:

  • You have 50 skills installed, but only 1 was used this session—only the full content of that one consumes tokens.
  • The Level 0 skill list (~3,000 tokens) is always loaded at session startup, letting the agent know which skills are available.
  • The rest is loaded only when the agent determines it's needed—no usage, no cost.

Progressive disclosure is what distinguishes the skill system fromStuffing all documentation into the system promptThis is the key design. It ensures the skill count can grow indefinitely while the per-session token cost remains essentially constant.

/learn command: generate a skill from a source with one click

/learnIt's a shortcut to quickly turn what you already know—or a pile of reference materials—into reusable skills, without hand-writing SKILL.md.

It is open-ended: point to anything you can describe, and the agent uses its existing tools to gather material, then generates the skill following standard authoring conventions.

Example

# Learn from the local SDK or documentation directory (read using read_file / search_files)
/learn ~/projects/REST client in acme-sdk, focusing on authentication and pagination

# Learn from online documentation pages (using web_extract)
/learn https://docs.example.com/api/quickstart

# Learn from the workflow you just completed
/learn the steps I just took to deploy the staging server

# Learn from pasted notes or described processes
/learn reimbursement process: open the portal, create a new expense report, attach receipts, and submit

How /learn works

The entire process is divided into three steps:

  1. The agent uses existing tools to collect source material (reading files, scraping web pages, analyzing the current conversation)
  2. Drafts SKILL.md following the official Skill authoring standards (including ≤60-character description, standard section order, Hermes tool framework, no fabricated commands)
  3. Throughskill_manageTool saving — if enabledwrite_approval, approval is requested first

/learn is available in CLI, message gateway, TUI, and Dashboard with identical behavior. The Dashboard's Skills page also provides a graphicalLearn a skillpanel, containing three input fields: directory, URL, and free text.

Agent automatically creates skills

This is the most distinctive part of Hermes's skill system: Hermes learns from experience by saving reusable processes as skills.

When it solves a complex problem, discovers a workflow, or is corrected, it can persist this knowledge as skill documents to be loaded in future sessions.

Skills accumulate over time, making the agent increasingly adept at handling your specific tasks and environment.

Controlling skill write permissions

By default, the agent is free to create and modify skills.

After enabling approval mode, the agent will first request your confirmation every time it wants to create or modify a skill:

Example

# File path: ~/.hermes/config.yaml
# Enable skill write approval
skills:
  write_approval: true   # default false

With write_approval enabled, you can preview the skill content the agent intends to write before deciding whether to approve. This is an important security boundary—skill files have no signed provenance information and cannot distinguishWritten by the Agent itselfandManually placed in the directory。

Conditional activation: intelligent show/hide mechanism

Skills can be filtered based on tools available in the current sessionAutomatically show or hide, no manual management needed.

This is very useful in multi-environment deployments—the same skill list automatically adapts across different environments.

Example

# Conditional activation configuration in SKILL.md frontmatter metadata
metadata:
  hermes:
    fallback_for_toolsets: [web]      # Only display when web toolset is unavailable
    requires_toolsets: [terminal]     # Only display when the terminal toolset is available
    fallback_for_tools: [web_search]  # Only display when the web_search tool is unavailable
    requires_tools: [terminal]        # Only show when the terminal tool is available
FieldsBehavior
fallback_for_toolsetsThe listed toolsetavailableWhen hidden,unavailableshown when
requires_toolsetsThe listed toolsetavailableWhen shown,unavailablehidden when
fallback_for_toolsSame as above, but for specific tools rather than tool sets
requires_toolsSame as above, but for specific tools

Practical Examples: Built-induckduckgo-searchSkill usedfallback_for_toolsets: [web]。

When you have configured a Firecrawl API Key (web tool set available), this skill is automatically hidden and the agent directly usesweb_search。

When the API Key is missing (web tool set unavailable), the DuckDuckGo skill automatically appears as a fallback.

Skill Bundle: combined loading

A skill pack is a YAML file that combines multiple skills under a single slash command.

Run/<bundle-name>When triggered, all skills listed in the pack load simultaneously—suitable for scenarios where a task always requires the same set of skills.

Create a skill package

Example

# Create backend development skill pack, combining three skills
hermes bundles create backend-dev \
  --skill github-code-review \
  --skill test-driven-development \
  --skill github-pr-workflow \
  -d "Backend feature development — code review, testing, PR workflow"

When using:

Example

# Load three skills simultaneously with one command.
/backend-dev refactor authentication middleware

Manually creating skills: getting started in five minutes

Skills are just Markdown files with YAML frontmatter metadata.

Creating a skill takes less than five minutes, no registration required, just put it in~/.hermes/skills/You can use it.

Step 1: Create a directory

Example

# Create skill directory (category/skill name)
mkdir -p ~/.hermes/skills/my-category/my-skill

Step 2: Write SKILL.md

Example

---
name: fly-deploy
description: Deploy the Python application to Fly.io, including environment variables and persistent volume configuration.
version: 1.0.0
metadata:
  hermes:
    tags: [python, deployment, fly.io]
    category: devops
    requires_toolsets: [terminal]
---

# Deploy Python application to Fly.io

## When to Use
- Users need to deploy Python applications (Flask/FastAPI/Django) to Fly.io
- Need to configure environment variables or Volume persistent storage
- Not for: non-Python applications, or using other cloud platforms

## Procedure
1. Check whether fly CLI is installed: fly version
2. Log in to Fly: fly auth login
3. Initialize in the project root directory: fly launch
4. Configure fly.toml (check the [build] and [http_service] sections)
5. Set the necessary secret: fly secrets set KEY=VALUE
6. Deploy: fly deploy
7. Check logs: fly logs

## Pitfalls
- fly launch will automatically detect Python apps and generate a Dockerfile,
In most cases, no need to write manually
Environment variables are set via fly secrets set rather than through a .env file
(.env will not be uploaded)
- Free plan has a monthly machine runtime limit; long-running applications are recommended to upgrade

## Verification
fly status # Check application status
fly open # Open the app in the browser

Security considerations for skills

Write approval gating

Skill files have no signed provenance information—cannot distinguishWritten by the Agent itselfandManually placed in the directory。

Write approval mechanism andpending/Directory management is a key security boundary.

After approval is enabled,write_approval: truecauses all skill write operations (including automatic creation initiated by the agent) to be staged as pending approval; you review before deciding whether to allow the write.

Security scan

Skill content is threat-scanned before loading, detecting malicious patterns such as prompt injection, backdoor installation instructions, etc.

Content matching threat patterns is replaced with[BLOCKED: ...]placeholder, preventing it from reaching the model—the file itself is not deleted, only the threatening content is blocked.

External skill directory

If you maintain skills outside of Hermes—for example, one shared by multiple AI tools~/.agents/skills/Directories — lets Hermes scan these directories simultaneously.

Example

# File path: ~/.hermes/config.yaml
# Configure external skill directory
skills:
  external_dirs:
    - ~/.agents/skills
    - /home/shared/team-skills
    - ${SKILLS_REPO}/skills

Path Support~expand and${VAR}Environment variable substitution.

Important Rules：

  • Local directory (~/.hermes/skills/) takes priority—when skills share the same name, the local version overrides the external version
  • External directories are not write-protection boundaries: if the Hermes process has write permissions, the Agent can modify skills in external directories.
